# Bugs found in this repository while porting its work downstream (2026-09-30)

Defects found in **this** repo while harvesting its 2026-09-28/29 work (`workflows-core` 1.8.0 /
1.8.1) into the two downstream editions. These are *not* ports — they are gaps where this repo is
behind, or wrong, and need a fix decision here.

**Naming note:** this repository forbids naming its downstream editions or their organisation
anywhere outside `CHANGELOG.md` (`scripts/check-docs.sh` check 19, `EDITION_FORBIDDEN_B64`), so they
are referred to below as "the Claude edition" and "the Copilot edition". That gate is why this file
reads the way it does; it is not vagueness.

Status: `open` = logged only; `fixed` = fixed on a branch in this repo.

| id | where | defect | severity | status |
|----|-------|--------|----------|--------|
| AW-1 | `plugins/workflows-core/references/cost-prices.yaml` | **Fable 5.1 cache reads were priced 4x high.** The table keyed only `claude-fable-5` (`cache_read: 1.0`) and its comment asserted "The undated key is a prefix of claude-fable-5-1, so the longest-prefix rule prices both from this one entry." That is true of `input`/`output` and **false of `cache_read`**, the field that dominates a cached agentic session: Fable 5.1 bills cache reads at 0.025x input (**$0.25**), not the 0.1x ($1.00) every other model here uses — a per-model exception on the pricing page, re-verified 2026-09-30. Longest-prefix therefore priced every Fable 5.1 cache read at $1.00, 4x high, and silently, because the prefix key matched and no `unpriced-model` note fired. The Claude edition fixed this in its own 2.61.1 and keys both ids separately with the trap documented. **Fixed:** both keys now present and separate, the false claim in the comment replaced with a statement of why it was false, and the header's cache-multiplier exception list now names Fable 5.1 alongside Opus 5.5. | MED | fixed |
| AW-2 | `references/cost-prices.yaml`, `references/model-routing/classification.md` §2/§2.1, 41 command references, 2 docs pages | **`claude-sonnet-5-5` was absent from the routing chains and the price table**, so no routing path could select the current Sonnet — §2.1's detection chain still headed with `claude-sonnet-5`. Pricing was correct only by coincidence: `claude-sonnet-5` is a strict prefix of `claude-sonnet-5-5` and the two rates currently match, which is exactly the latent shape that priced Opus 5.5 ~25% high off `claude-opus-5`'s key until 1.7.5. A reprice of either model turns the coincidence into a silent error. **Fixed:** added at the head of §2.1 and as §2's first Sonnet fallback; the 41 literal chain-head references across the commands and the 2 `docs/reference/model-routing.md` chains moved with it; `run-flags.md`'s unpriced-model check and both docs pages' "family's newest model" claim now name Sonnet 5.5; keyed explicitly in `cost-prices.yaml` with the prefix trap documented. Same gap existed in the Claude edition and was fixed there in the same round. | MED | fixed |
| AW-3 | `CLAUDE.md` | **Withdrawn as logged — a unit error, not a defect.** This row said `CLAUDE.md` was at "36,197 characters" and therefore past `validate-catalog.py`'s 36,000 warn threshold, shipping a standing warning. 36,197 is its size in **bytes** (`wc -c`; `wc -m` also counts bytes under a container with no locale set). It is **35,928 characters**, which is the unit the gate counts, so it sits 72 *under* the line and the gate reports zero warnings — correctly. The same bytes-for-characters slip is what made check 6 of `check-docs.sh` wrong under `mawk` a round earlier. **What is true and worth acting on:** three instruction files are saturated rather than over — `CLAUDE.md` at 35,928 of 36,000, `.claude/rules/gates.md` at 19,966 of 20,000 and `.claude/rules/docs-workflows.md` at 19,887 of 20,000 — so the next sentence added to any of them tips its warning. That is headroom to create deliberately, not a breach to repair. | LOW | withdrawn (mis-measured); headroom note stands |
| AW-4 | `scripts/check-docs.sh` `PLUGIN_RELS` + `docs/maintainers/rationale.md` | **The docs gate skips three shipped plugins, and it was undecided whether that was intentional.** `73bb7980` scoped the `CLAUDE.md` docs rule down to `PLUGIN_RELS` rather than widening the list, which made the instruction accurate and left the gap documented rather than decided. **Decided:** `obsidian-llm-wiki`, `prose-style` and `acli` ship **no `docs/` tree at all**, so adding them to `PLUGIN_RELS` would not gate them — it would turn the build red on the first run, since check 1 has no `docs/README.md` to resolve against and check 9 no prose to count. Widening is therefore authoring three documentation trees (a feature), not a list edit. Recorded in `rationale.md` as a deliberate five, with the trigger that would change it: a plugin outgrowing its README gets a `docs/` tree and joins `PLUGIN_RELS` in the same change, because a tree that exists and is ungated is the one state this does not tolerate. | LOW | fixed (decided + recorded) |
| AW-5 | `scripts/check-docs.sh` check 6 | **Character count under-counts malformed UTF-8.** The count subtracts every `0x80`–`0xBF` byte as a UTF-8 continuation byte, so stray continuation bytes with no lead byte are subtracted too and a malformed cell under-counts. No shipped doc is malformed (verified by `iconv` round-trip in an earlier round). Documented in the check's own comment in all three editions rather than guarded; recorded here so the shared body stays consistent if anyone hardens it. | LOW | documented |

| AW-6 | `plugins/workflows-core/scripts/session-cost.py` | **A Skill-tool invocation never cut the cost window.** `command_envelope` read user messages only, and the `<command-name>` envelope is emitted solely when the user TYPES the command; a prose request reaching the command through the Skill tool is only an assistant `tool_use` block.
