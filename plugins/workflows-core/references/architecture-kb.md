# Architecture knowledge base (shared reference)

The team's architecture decisions, kept under `$SPECS_PATH/architecture/`: one record per `[AD#N]` of the ARDs on the specs repository's default branch. `/product-workflows:harvest-decisions` writes it with product-workflows' bundled script `scripts/architecture-harvest.py`, run with `--layout prd`; `/product-workflows:create-ard`'s architecture grounding reads it as its **team root** (`workflows-core:architecture-grounding`); a later ARD departs from a record only with `**Supersedes:**` (`product-workflows:ard-format` § Architecture governance). This file is the format authority. The script implements it, and a change here is a change to the script and its `--selftest` in the same commit.

Consumers: `/product-workflows:harvest-decisions` (the only writer), `/product-workflows:create-ard` through `architecture-grounding` and `architecture-grounder` (readers), `ard-reviewer` (checks that a `Supersedes` link resolves to a record).

## 1. Layout

```
$SPECS_PATH/architecture/
  README.md          generated: what the folder is, "change the ARD, not the records", a table of live records
  index.yaml         generated catalog: one entry per record — id, type: decision, title, status, path, tags — sorted by id
  decisions/<id>.md  one record per harvested [AD#N]
```

It is the catalog-and-`decisions/` layout `architecture-grounder` recognises, so the folder passes `workflows-core:architecture-grounding`'s validity gate as it stands. The first harvest that finds an ARD creates the folder; one that finds none writes nothing, so the folder never exists empty — an `index.yaml` with nothing behind it would turn grounding ON with nothing to read.

## 2. Identity

A record's id is `<KEY>-AD<N>`, `<KEY>` being the scope key of the ARD the decision came from: the `key:` of a `PRD-` folder's `ard.md` or of an `EPIC-` folder's `ard.md`, and `<KEY>-<area>` for an `ard-<area>.md` — read from the ARD's own `key:`, else from its `<KIND>-<KEY>-<slug>` folder name; the PRD a record belongs to is the nearest `PRD-` folder holding the ARD (`workflows-core:addressing` §2). The key grammar ends in a numeric segment, so an id ending in `-AD<N>` is never a key. An `[AD#N]` is never renumbered (`ard-format.md` § Superseding a decision), so an id is stable for life. Two ARD paths with one key are a **key conflict**: both are reported and neither is harvested.

## 3. A record

```markdown
---
id: ACME-17-AD3
title: "<the decision's title>"
type: decision
status: accepted | superseded | withdrawn
scope: prd | epic | area
prd: ACME-17
epic: <EPIC-KEY | null>
source: "specifications/PRD-ACME-17-<slug>/ard.md"
components: ["<the PRD-level ARD's components: ids>"]
tags: ["<component ids>", "<grounded_repos slugs>"]
superseded_by: <record id>                 # only when superseded
---
<!-- Generated by /harvest-decisions from the source ARD — change the ARD, not this file. -->
# ACME-17-AD3: <title>

**Binds:** …

**Prevents:** …

**Rule:** …

**Alternatives:** …

Source: [<ARD title>, [AD#3]](../../specifications/…/ard.md)

## Applied in

- [<path>](../../<path>)

## Deviated in

- [<path>](../../<path>) — <what deviates> — <why>
```

Every field is copied verbatim from the ARD, and **Supersedes**, **Superseded by** and **Withdrawn** follow **Alternatives** where the ARD carries them — a `Supersedes` link re-targeted to the record it names (`<id>.md`), since the ARD's own link is relative to the ARD. An empty *Applied in* or *Deviated in* reads `None.` An Epic or area record takes `components` from its PRD-level ARD, the only ARD that carries the key.

## 4. Statuses

- `accepted` — the decision is live in its ARD.
- `superseded` — its ARD gives it `**Superseded by:** [AD#M]` (`superseded_by: <KEY>-AD<M>`), or a live decision in another PRD's ARD names it in `**Supersedes:**`: `superseded_by:` is then that decision's record, and the record gains `**Superseded by:** [<id> <title>](<id>.md)`.
- `withdrawn` — its ARD gives it `**Withdrawn:**`.

A superseded or withdrawn record binds nothing, and `architecture-grounder` skips it. A `Supersedes` is applied only from a live decision, to an `accepted` record of **another** PRD, and only when no second live decision claims the same record; anything else is a problem (§8) and changes nothing. A decision that replaces one carrying `Supersedes` repeats the line where it still replaces that record — otherwise the record is live again at the next harvest.

## 5. Citations — Applied in, Deviated in

The harvest reads every markdown file in the folder tree of the record's PRD, except the ARDs themselves, `revisions/`, `dev-workflows/`, `attachments/` and any `*-import/` folder — a tracker export, whose copies would count a deviation twice:

- **Applied in** — each `design.md` that mentions the decision's `[AD#N]` outside a deviation line.
- **Deviated in** — each `- ARD deviation: [AD#N] — <what> — <why> — flag: architect` line (`workflows-core:ard-resolution` § Deviation-record convention), in any of those files, with its what and why.

A cited number resolves the way `workflows-core:ard-resolution` layers ARDs: inside an Epic's folder, that Epic's ARD when it holds the number, else the one area ARD of that Epic that does, else the PRD-level ARD. A number two area ARDs of one Epic both hold, with no Epic-level ARD holding it, is an **ambiguous citation**: reported, linked to neither.

## 6. What the harvest owns

The body and every frontmatter key in §3, rewritten on every run. Any other frontmatter key is preserved verbatim, after the owned keys — the room a later command needs to record what it did with a record. Hand edits to owned content are overwritten; the generated comment and the README say so.

## 7. Determinism

Every input is read from the default ref with `git`, never from the working tree — an uncommitted or unmerged ARD is invisible by construction. The output is a function of those inputs and the preserved keys, sorted by id, with no timestamp or sha in any file, so a harvest on an unchanged ref writes nothing. A record is never deleted: one whose ARD or decision is gone is kept unchanged and reported.

## 8. Problems

Problems never stop a harvest and never change its exit code; each leaves the records it touches as they were.

| Kind | Meaning | Fix |
|---|---|---|
| `unparseable` | a decision with no **Rule**, a duplicate number, a heading with no number, both **Superseded by** and **Withdrawn**, a **Superseded by** naming no `[AD#M]`, a **Supersedes** whose link text does not start with a record id, or an ARD outside a `PRD-` or `EPIC-` folder | refine the ARD (`/product-workflows:create-ard`) |
| `key-conflict` | two ARD paths with one scope key | remove or rename one of the two |
| `ambiguous-citation` | a cited number two area ARDs of one Epic both hold | cite it where only one ARD holds it |
| `supersedes-carrier-not-live` | a `Supersedes` on a superseded or withdrawn decision | repeat it on the replacing decision, or drop it |
| `supersedes-missing-target` | a `Supersedes` naming no record the harvest holds | correct the link |
| `supersedes-same-group` | a `Supersedes` naming a record of its own PRD | refine that ARD with `Superseded by` instead |
| `supersedes-target-not-accepted` | a `Supersedes` naming a record already superseded or withdrawn | name the live record that replaced it |
| `supersede-conflict` | two live decisions superseding one record | drop the `Supersedes` from one of the two ARDs |
| `source-missing` | a record whose ARD is no longer on the default branch | restore the ARD, or keep the record as history |
| `decision-missing` | a record whose decision is no longer in its ARD | restore the decision, or keep the record as history |

## Invariants

- Only `/product-workflows:harvest-decisions` writes here, through `workflows-core:phase-handoff`'s `handoff-to-main` on a `kb/` branch; nothing is ever deleted.
- Every input comes from the default ref; the working tree is only written.
- The format here and the script change together; the script's `--selftest` pins every rule above.
