# ia-planner Handoff Format

The input and output contract for `ia-planner`, read by the agent itself. Its input is the other half of `${CLAUDE_PLUGIN_ROOT}/references/handoff/docs-auditor.md`'s output: **`surfaces[]` and `unresolved[]` arrive verbatim from that block**, field for field, and nothing between the two agents reshapes them. The field names of a unit and of a tutorial candidate are `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/backlog-format.md` §1's; the page-`type` vocabulary, the four prioritisation signals and the churn guard are `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/coverage-model.md` §3 and §5's. Neither is restated here.

## Input

```yaml
surfaces:                              # docs-auditor's surfaces[], verbatim
  - id: order-placement
    kind: task
    title: "Place an order"
    roles: [customer, admin]
    evidence:
      - { repo: example-webapp, path: src/routes/orders/new.tsx }
    volatility: high                   # high | medium | low | unknown

audiences: [user, engineering]         # optional; both where the caller names none

unresolved:                            # optional; docs-auditor's unresolved[], verbatim — carried, never acted on
  - { kind: role, theme: <verbatim>, source: <repo name; "specs"; or several repo names>, reason: <one line> }

existing_units:                        # optional; on a --refresh run, the units already in the backlog
  - { id: U-001, surface: order-placement, audience: user, type: how-to,
      priority: 1, priority_reason: "blocks primary journey; 2 roles; 3 evidence paths across 2 repos" }

existing_tutorial_candidates:          # optional; on a --refresh run, the candidates already in the backlog
  - { role: customer, journey: [order-placement, payment], picked: false, unit: null }
```

Refuse to run without a **non-empty** `surfaces[]`, and without both `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/coverage-model.md` and `${CLAUDE_PLUGIN_ROOT}/references/docs-audit/backlog-format.md`. An empty `surfaces[]` is `docs-auditor`'s `NO_SURFACES`, which is the caller's to report rather than a plan for this agent to make; this agent is not dispatched on it.

**`surfaces[]` and the two reference files are evidence inputs; `audiences[]`, `unresolved[]`, `existing_units[]` and `existing_tutorial_candidates[]` are context inputs.** An unreadable evidence input is a hard stop and is never regenerated by other means; an unreadable context input degrades to absent and the degradation is recorded in `degraded[]`. The agent body states both tiers in full. **Not supplied and degraded are different states**: an initial run carries no `existing_units[]` and that is ordinary; a `--refresh` run whose `existing_units[]` would not read has lost its view of which cells are occupied, which ids are taken, and which stored `priority_reason` each comparison below is against, and the caller must know which of the two it is before it writes.

**No `model_routing:` block is passed.** This agent's tier is pinned by its own frontmatter (`model: opus`), and nothing in the agent reads a field of that block.

**This agent never asks a question.** It has no user: there is no `choices:` array in its return, no escalation, and no field the operator answers. The one judgement reserved for a person — which journey a role should learn first — reaches them as a `tutorial_candidates[]` entry with `picked: false`, which they set by editing the backlog.

## Output

```yaml
status: OK | PARTIAL | NO_UNITS | INPUT_MISSING

units:                                 # exactly backlog-format.md §1's fields for a unit
  - id: U-001
    surface: order-placement           # always a surface id from the supplied surfaces[]; never null
    journey: []                        # always empty here — a journey belongs to the tutorial mint, which is /docs-audit --refresh's
    title: "Place an order"
    audience: user                     # user | engineering
    visibility: public                 # defaults from audience; a departure is explained in notes
    type: how-to                       # coverage-model.md §3's vocabulary; never `tutorial`
    roles: [customer]
    priority: 1
    priority_reason: "blocks primary journey; 2 roles; 3 evidence paths across 2 repos"
    churn_adapted: false
    status: missing                    # always `missing` here
    page_path: null                    # always null here — no page exists yet
    walkthrough: null                  # always null here — no walkthrough exists yet; /docs-verify composes a user unit's later
    evidence: []                       # always empty here — a unit's own evidence is written only on a surface: null unit
    blocked_by: []                     # always empty here

priority_comparisons:                  # one per cell existing_units[] occupies whose surface is still in surfaces[]
  - unit: U-001                        # the existing unit's id — this is a comparison, never a mint
    surface: order-placement
    audience: user
    type: how-to
    stored_priority: 1
    stored_priority_reason: "blocks primary journey; 2 roles; 3 evidence paths across 2 repos"
    derived_priority: 2
    derived_priority_reason: "does not block; 2 roles; 1 evidence path across 1 repo; volatility low"

tutorial_candidates:                   # proposed, never picked; empty where audiences[] excludes `user`
  - role: customer
    journey: [order-placement, payment, order-tracking]   # surface ids, in the order somebody would meet them
    rationale: "shortest path through the three highest-priority customer tasks"
    picked: false                      # always false here
    unit: null                         # always null here

unresolved:                            # the input's unresolved[], echoed verbatim
  - { kind: role, theme: <verbatim>, source: <repo name; "specs"; or several repo names>, reason: <one line> }

degraded:                              # context inputs that were supplied and could not be read
  - input:  audiences | unresolved | existing_units | existing_tutorial_candidates
    reason: <one line>

notes: |
  <what the run's report needs and the blocks above do not carry: a surface that earned no unit
  and why; the type chosen for each `role` and `release` surface, with its reason, since §2 names
  a page shape for those two rather than a type; any `visibility` that departs from its audience
  default, with its reason; a role that got no candidate and why, or the whole block suppressed
  because `audiences` excludes `user`; a role whose existing candidate this run would have
  proposed a different journey for, with that journey named and nothing rewritten; an existing
  unit whose surface has left `surfaces[]`, so it got no comparison; the fact that the `role` kind
  was unresolved and signals 1 and 2 are therefore unmeasured rather than zero; and — where
  `existing_units` was not supplied — the fact that ids were minted from U-001 and cells were
  checked only within this return, so the caller must check both against the file before it
  writes.>
```

**`priority_comparisons[]` is what makes a `--refresh` able to re-rank, and it is a comparison rather than a mint.** `backlog-format.md` §1 fixes the test — where the stored `priority_reason` is exactly the reason this run derives, nothing was edited and both fields take the new values; where it differs, both stored values stand and the run reports the pair — and that test needs a priority derived on today's signals for a unit that already exists. This agent supplies that pair and applies nothing: it mints no unit for an occupied cell, touches no id, and leaves the file-level comparison to the orchestrator, which holds the file. The block is empty on an initial run, and on a refresh it carries one entry per occupied cell **whose surface is still in `surfaces[]`** — a unit whose surface has gone has nothing to re-derive from, and `notes` names it instead.

## Status codes

| Status | Meaning |
|---|---|
| `OK` | `units[]` is non-empty, every surface in `surfaces[]` was considered, and `degraded[]` is empty. A non-empty `unresolved[]` does **not** make a run `PARTIAL` — it is the input's finding, carried through, and this agent resolved nothing and lost nothing. |
| `PARTIAL` | `units[]` is non-empty **and** at least one of these holds: a context input degraded, or a surface could not be planned and was skipped — a `kind` outside `coverage-model.md` §2's seven, or a surface carrying an empty `evidence[]`, neither of which `docs-auditor` emits. `notes` names each one. |
| `NO_UNITS` | `units[]` is empty although `surfaces[]` was not. This is reachable and is not an error: `audiences: [engineering]` over a set of `task` and `concept` surfaces mints nothing, because those kinds feed user types. `notes` says which of the two it was — a filter that excluded everything, or surfaces that earned nothing. `priority_comparisons[]` may still be non-empty, since an occupied cell is re-derived rather than minted into. |
| `INPUT_MISSING` | The refusal above fired: `surfaces[]` was empty or absent, or an evidence input could not be read. The return carries this status and the name of what was absent, **and no other block**. It is distinct from `NO_UNITS`, which is a completed plan that earned nothing; this one is a run that never started. |

**`tutorial_candidates[]` is empty on `NO_UNITS`, and that is derived rather than stipulated.** A journey is built from the `task` surfaces behind this run's ranked units, so both routes to `NO_UNITS` close it: where `audiences[]` excludes `user` the block is suppressed outright, because `tutorial` is a user type and a pick there would mint a unit the same filter refuses; and where `user` is included, any `task` surface would have earned a `how-to` and the run would not be `NO_UNITS`, so no `task` surface was there to string together. On an `OK` run it can still be empty, where no role had a journey worth proposing. It is never the reason a status is `PARTIAL`, because proposing no candidate is a judgement rather than a failure — `notes` carries the reason in every one of those cases.
