# Glossary

The terms this plugin's pages use, often before they define them. Each entry says what the term means in a sentence or two and links the page that owns it, where you will find the detail.

- **`allocate-only`** — The mode [`/brd-split`](../commands/brd-split.md#two-modes) runs in on a slice. It walks the slice's own ledger rows to a fate and creates nothing below the slice; its walk offers `covered-here` where a root's walk offers `covered-by`. On a root the mode is `full`.
- **ARD** — Architecture Requirements/Decision Document: `ard.md`, the architecture decisions for a PRD or for one of its Epics, each decision an `[AD#N]`. [`/create-ard`](../commands/create-ard.md) writes it into the PRD's folder, or into the Epic's folder for one Epic.
- **BRD** — A business requirements document a customer supplied, taken in as it is. Its folder, `BRD-<KEY>-<slug>/`, is a container: a PRD, an ARD and a specification are written in the slices under it, never in it. [BRD workflow](../brd-workflow.md).
- **BRD route** — The six commands that take a BRD from intake to customer-reviewed decisions: `/brd-intake`, `/brd-split`, `/prd-ground`, `/brd-interview`, `/brd-package` and `/brd-reconcile`. It hands over to `/create-prd`, `/create-ard` and `/specify`, run on a slice. [BRD workflow](../brd-workflow.md).
- **Build ladder** — The commands that write a PRD and carry it toward shipped code: `/create-prd`, `/create-ard`, `/epics` and `/specify` here, and the companion `dev-workflows` plugin's commands after them. An effort proposal gates none of them. [Workflow overview](../workflow.md).
- **Bundle** — The dated folder, `bundle-<YYYYMMDD>/`, that [`/brd-package`](../commands/brd-package.md) builds for the customer: plain markdown, with a self-contained prompt they paste into an AI agent of their own. A dated bundle is never rewritten.
- **Coverage ledger** — `coverage-ledger.md`: one row per `[BR#n]` requirement, each with its disposition. `/brd-intake` writes the root's, and `/brd-split` writes each slice's, both with every row `unallocated`; `/brd-split` then walks every row to a fate. [What lands where](../brd-workflow.md#what-lands-where).
- **`covered-here`** — The disposition of a ledger row the slice itself will build. Only a slice carries it, never a root, and a slice with one is PRD-eligible. [`/brd-split`](../commands/brd-split.md#two-modes).
- **Customer review** — The one file the customer returns after reading the bundle: committed beside the bundle by pull request, or sent back. [`/brd-reconcile`](../commands/brd-reconcile.md) reads it and freezes each answer you confirm as a `[CD#n]` decision.
- **Decision register** — A slice's `decisions.md`: `[VD#n]` delivery-team decisions and `[AS#n]` assumptions from `/brd-interview` (an `[AS#n]` from `/create-prd` too), and `[CD#n]` customer decisions from `/brd-reconcile`. Only a record whose status reads `decided` is frozen. [`/brd-interview`](../commands/brd-interview.md).
- **Defect log** — The root's `brd/brd-defect-log.md`: one `[DEF#n]` for each defect in the customer's document that you confirmed at intake, `open` until a later step resolves it. A slice uses its parent's. [`/brd-intake`](../commands/brd-intake.md).
- **Disposition** — A ledger row's fate, exactly one of six: `covered-here` (built in this slice), `covered-by: <KEY>` (a named slice — or, on a slice, a sibling or the parent — owns it), `deferred-to: <KEY>` (kept as this BRD's obligation, not built now), `rejected` (not built, citing a defect or a customer decision), `superseded-by: [BR#n]` (replaced by another requirement), and `unallocated`, the state every row starts in. [`/brd-split`](../commands/brd-split.md).
- **Effort proposal** — `proposal.md`: an estimate of a requirement set in hours, never money, by work package and role. `/prd-proposal` writes one for a folder and `/brd-proposal` one for a BRD's slices; both are optional, and nothing on the build ladder waits on them. [Effort proposals](proposal-format.md).
- **Epic** — A part of a PRD that is specified, designed and built on its own. [`/epics`](../commands/epics.md) drafts each in an `EPIC-<PRD-KEY>-NN-<slug>/` folder below the PRD.
- **Frame set** — A folder of exported design images under a folder's reserved `design/` directory, one subdirectory per set, with an index naming what each frame shows. Grounding skips a set with no index; the companion `workflows-core` plugin's `/workflows-core:frames` writes one. [What lands where](../brd-workflow.md#what-lands-where).
- **`[G]`, `[V]` and `[C]`** — The tag `/brd-interview` gives every open question before it asks anything, which decides who may answer it: a `[G]` is answered from the grounding findings and never put to a person, a `[V]` is a delivery-side decision you make with your reasons recorded, and a `[C]` is a business decision held for the customer. [`/brd-interview`](../commands/brd-interview.md#the-tag-decides-who-may-answer).
- **Grounding** — Checking each requirement against real code at a pinned commit, and against exported frame sets, before anyone relies on it. [`/prd-ground`](../commands/prd-ground.md) writes `[CG#n]` code findings and `[DG#n]` design findings under the folder's `grounding/`, and a second agent re-derives every finding blind before it counts. Documentation grounding, against `$DOCS_PATH`, is a separate and optional check that a new document does not contradict what is already published.
- **Handoff** — The step that ends a command which writes a document: it offers to cut a plugin branch, commit, push and open a pull request against the specs repo's default branch. A phase is finished only once that pull request is merged. [The handover model](../roles-and-phases.md#the-handover-model).
- **Horizon** — On the BRD route, every grounding finding is `current` or `will-change`. `will-change` means the finding is true of the pinned commit, but a frozen decision of a prerequisite BRD, declared with `--depends-on`, makes it false once that decision is built. [`/prd-ground`](../commands/prd-ground.md).
- **Idea brief** — `idea.md`, the one-page brief [`/idea`](../commands/idea.md) writes into the PRD folder its key names, which `/create-prd` turns into a PRD. It is `status: refined` only while no `[NEEDS CLARIFICATION]` marker is open; otherwise it is a draft, and a draft is never handed off.
- **Idea route** — The way into a PRD that starts from your own idea: `/idea`, then `/create-prd`. The other way in is the BRD route. [Workflow overview](../workflow.md).
- **Inventory** — `brd/brd-inventory.md`: the `[BR#n]` requirement rows `/brd-intake` extracts from the customer's document. A slice holds a copy of the rows it claims. [`/brd-intake`](../commands/brd-intake.md).
- **Key** — The name you choose for a folder under `$SPECS_PATH/specifications/`, such as `ACME-77`. It must match `^[A-Z][A-Z0-9_]*(-\d+)+$`, and nothing looks it up in a tracker. A slice's or an Epic's key is usually its parent's plus a two-digit segment, such as `ACME-77-01`. [Getting started](../getting-started.md#your-first-run).
- **`<merge-clause>`** — A placeholder in a next-step offer, filled in from how the run's handoff ended. It says what must reach the default branch before the command the offer names can run — for example `(once the pull request above is merged)` — or that it can run now. [BRD workflow](../brd-workflow.md).
- **`[NEEDS CLARIFICATION]`** — A marker in `idea.md` for a question left open: a high-impact gap the bounded grill did not close (three at most), or a theme the optional code scan could not settle. Any open marker keeps the brief a draft. [`/idea`](../commands/idea.md#gates).
- **PA** — Product architecture: the optional role that writes ARDs with `/create-ard`, keeps the team's architecture decisions with `/harvest-decisions`, and proposes organisation ADRs from them with `/promote-decisions`. [Roles and phases](../roles-and-phases.md#pa--product-architecture).
- **PE** — Product engineering: the role that breaks a PRD into Epics with `/epics` and writes specifications with `/specify` and `/update-spec`. [Roles and phases](../roles-and-phases.md#pe--product-engineering).
- **Plugin branch** — A branch the commands cut in the specs repo to hand a document off, named for the step and the folder: `idea/`, `prd/`, `ard/`, `spec/`, `epics/`, `brd/` and the rest, followed by the folder's key and slug. A command whose input sits on an unmerged plugin branch stops and names it. [The handover model](../roles-and-phases.md#the-handover-model).
- **PM** — Product management: the role that refines ideas with `/idea`, writes and updates PRDs, and owns the BRD route end to end. [Roles and phases](../roles-and-phases.md#pm--product-management).
- **PRD** — Product Requirements Document: `prd.md`, which [`/create-prd`](../commands/create-prd.md) writes into a `PRD-<KEY>-<slug>/` folder and `/update-prd` revises. On the BRD route it is written in a slice.
- **PRD-eligible** — A slice with at least one claimed ledger row `covered-here`. `/create-prd` refuses a slice that is not, and also one with a claimed row still `unallocated`. [BRD workflow](../brd-workflow.md).
- **Readiness tier** — The grade, 1 to 4, printed on an effort proposal. It says what the folder held when it was priced — a PRD; then verified grounding and a settled decision register; then an ARD; then a specification — and caps the confidence of every work package. [Effort proposals](proposal-format.md#readiness-is-graded-not-gated).
- **Root** — The `BRD-` folder `/brd-intake` creates for a customer's document. It holds the copied source, the inventory, the defect log, the root ledger and the slices. It is never ground, interviewed, packaged or reconciled, and no PRD is written in it. [BRD workflow](../brd-workflow.md).
- **Round** — One pass of `/brd-interview` over a slice's open questions, recorded in `interview/round-<N>.md`; `--round N` resumes or re-opens one. [`/brd-interview`](../commands/brd-interview.md).
- **Sibling re-cut** — A re-run of `/brd-split` on a fully allocated root, given an instruction, that moves a requirement one slice has deferred onto a sibling slice that has not been interviewed yet. [BRD workflow](../brd-workflow.md).
- **Slice** — A `PRD-` folder `/brd-split` carves inside a BRD folder, one level deep, claiming some of the BRD's requirements. The slice is where they are ground, decided and sent to the customer, and where the PRD, ARD and specification for them are written. Its `brd-link.md` names its parent. [BRD workflow](../brd-workflow.md).
- **Specs repo** — The git repository `$SPECS_PATH` names, holding every document the commands write under `specifications/`. A command hands its document to the next one by landing it on this repository's default branch. [Getting started](../getting-started.md#specs_path).
