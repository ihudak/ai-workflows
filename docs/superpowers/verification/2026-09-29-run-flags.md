## 9. The free-text commands (run-flags.md §3 step 1) each state the before/after/never-inside rule

`run-flags.md` §3 step 1 names eight members: `/feedback`, `/prompt`, `/prompt-brainstorm`, `/prompt-grill-me`, `/implement`, `/idea`, `/brd-split`, `/document` (direct mode). Checked each command's own body and its `docs/commands/*.md` page for a sentence stating that a run flag is protected before/after the free text and never treated as text-internal:

| Command | Body wording | Docs page wording |
|---|---|---|
| `/feedback` | "stripped only before or after the note, never inside it" | same phrase, present |
| `/prompt` | "stripped only before or after the corrective request, never inside it" | same phrase, present |
| `/prompt-brainstorm` | "stripped only before or after the corrective request, never inside it" | same phrase, present |
| `/prompt-grill-me` | "stripped only before or after the corrective request, never inside it" | same phrase, present |
| `/document` | Usage line: "the run flags may stand before or after the free text, never inside it" (literal); Phase 0 body: "the prose span begins there, kept exactly as typed even where it contains a flag name" (equivalent, longer form for its leading/trailing-run mechanics) | "a run flag in either position is stripped, one written inside the text itself is kept as text, never read as a flag" (equivalent) |
| `/implement` | "a run-flag token before the prompt begins, or in a trailing run at the very end ... is stripped, but one written inside the prompt itself is kept as prompt text" (equivalent) | "one written inside the prompt itself is kept as prompt text" (equivalent) |
| `/idea` | "a run flag written before the key, or forming a trailing run at the very end, is stripped, but one written inside the prompt itself is kept as prompt text ... even where it looks like a flag" (equivalent) | "one written elsewhere — even immediately after the key — is kept as prompt text unless that trailing run reaches back far enough to include it" (equivalent) |
| `/brd-split` | "stripped ... only where they sit before the key, or as a trailing run at the very end ... a flag name included wherever the operator typed one as instruction text instead of as a trailing flag" (equivalent) | "stripped only where they are written before the key, or form a trailing run after the instruction ... a flag written right after the key, with no such trailing run reaching back to it, is instruction text" (equivalent) |

**Result: all 8×2 = 16 locations state the rule; none is missing it.** The exact sentence "before or after the text, never inside it" is literal in 5 of the 8 command bodies (`/feedback`, `/prompt`, `/prompt-brainstorm`, `/prompt-grill-me`, and `/document`'s Usage line) and in the 4 simple logging commands' docs pages; the other 4 (`/implement`, `/idea`, `/brd-split`, and `/document`'s own Phase-0 body/docs-page prose) state the identical rule in the longer leading-run/trailing-run phrasing their own — more complex — free-text carve-out requires (§3 step 1's own distinction between the simple four and the four with a leading region bounded by a key/`@path`/`--no-commit`). This is a documented wording difference, not a missing rule: every one of the 16 sites was read and each asserts the same semantic content (flags stripped only at the edges, kept verbatim as text everywhere between them). Not a check failure.
