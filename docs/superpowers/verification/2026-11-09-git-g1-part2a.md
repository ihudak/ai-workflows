### The citing paragraphs (N7)

Which paragraphs of a command still read the reference when the run meets them. **Scope:** every blank-line-separated paragraph of `plugins/*/commands/*.md` that cites the reference, by holding `workflows-core:specs-repo-git`, `specs-repo-git.md` or `args: "specs-repo-git`. **Served:** a paragraph that makes a start or end request — `specs-repo-git specs-preflight` or `commit-artifacts`, a `` `specs-preflight` `` or `` `commit-artifacts` `` entry point, or `workflows-core:specs-git` — or one that cites at least one section, every one of them §3.2 in a sentence naming the run key set, §5 or §6. **Reading:** every other citing paragraph, a paragraph citing no section included.

Which sections a paragraph cites can be read two ways, and the recipe gives both. *Every section in the paragraph* counts each `§` it holds, whatever reference it belongs to. *Its own sections* reads each `§` as a section of the reference the paragraph named last before it, so a section of another reference in the same paragraph does not count. The second is the one the loader acts on: its paragraph serves a citation of the reference's §3.2 run key set, §5 or §6, wherever another reference's section stands beside it. Each paragraph's whitespace is collapsed first, so a hard-wrapped "run key set" still counts. Run from the repository root as `python3 -I citing.py "$SCRATCH/tree-<sha>"`:

```python
import glob, os, re, sys

root = sys.argv[1]
CITES = re.compile(r'workflows-core:specs-repo-git|specs-repo-git\.md|args: "specs-repo-git')
REQUEST = re.compile(r'specs-repo-git (specs-preflight|commit-artifacts)|`(specs-preflight|commit-artifacts)` entry point|workflows-core:specs-git')
TOKEN = re.compile(r'(?P<ref>[a-z][a-z-]*:[a-z][a-z0-9/-]*|[a-z][a-z0-9-]*\.md\b|args: "[a-z][a-z-]*)|§ ?(?P<sec>\d+(?:\.\d+)*)')

def sentence(p, i):  # the sentence of p holding offset i
    return p[p.rfind(". ", 0, i) + 1:(p.find(". ", i) + 1) or len(p)]
```
