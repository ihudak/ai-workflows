## 4. The cost finding and the user's decisions

**Reference splitting has not clearly paid.**
- **Part 1.** It cost +6% to +56% per run over its baselines, from the early whole reads of the procedure references that part 1's loader rules require: `phase-handoff`, `specs-repo-git`, `addressing`, `classification`, `run-flags`.
- **D's first round.** D split the one reference whose split the dependency maps justified, `require-on-main`. Against the corrected part-1 figures, D's first five runs total $110.28 against part 1's $104.74, which is +5%: level with part 1, within run-to-run variance.
- **D's latest runs.** These are the three re-runs and runs 3 and 4. They total $118.92, +14%. The rise over the first round is +$8.64 (run 1 −$1.66, run 2 +$0.35, run 5 +$9.95). About $4 of it is the fixes' intended work — the design reviewer, +$2.15, and run 2's verifiers, +$1.87 — plus 8d's premise read. About $2.3 is run 5's re-run following the loader as written. The rest is variance (Ruling 32).
- **Quality.** The final verdicts are two equivalent (runs 1 and 3) and three D better (runs 2, 4 and 5). After the fixes, runs 2 and 5 turned into D wins (8b and 8e; 8d), and run 1 became equivalent (8a). Run 4's small edge was variance, from before any fix. None came from the split.
- **Conclusion.** The split saves where a run reads the whole reference early and keeps it: about 69k characters carried by every later call of a `require-on-main` consumer. That saving is smaller than the variance in how runs invoke the loader. So D does not show that splitting references lowers cost.

**What follows.** The user decided, on 2026-10-24, to drop lean context's queued next part, the split of `implement.md` by part, because a restructured `/implement` would throw it away. The sub-project after D is a different one: fewer `code-writer` splits and Epics sized by coupling (below).

**The decision that started D** is part 1's (part 1's record §4, 2026-10-22, 09:3xZ): split the large procedure references by entry point, and make `escalation-rules core` an explicit load step in every asking command.
