It is the controller's `progress.md` copied byte for byte, save the internal edition's name on its line 46, which the repository's check 19 forbids and which is written `<internal-edition>` there. Every *line* this file cites, and the *Line* column below, is that ledger file's own line: `progress.md`'s line *n* is its line *n* + 5, so the ledger's first ruling, `progress.md` line 9, is line 14 there.

A ruling is a decision the controller took in place of stopping to ask. Here are all of them, so that the maintainer can read them in one place and rework any that was wrong: the plan's rulings table (R1 to R23) and its own calls (P1 to P7), in the plan's order, and then every line of the ledger that begins `Ruling`, in the order taken, grouped by task, then the merge, then the final review. Each gives what was decided, why, and what it costs if it was wrong. The cost is always the source's own: the rules table's *Cost if wrong* column, or the ledger line's `costs:` clause, quoted. Where the source states none, the cell says so. Nothing here is a cost this file thought up.

The run's scratch directory, `.superpowers/sdd/2026-11-17-ladder-order-b4-brd-route/`, is git-ignored and is deleted with the worktree. It holds `implementer-rules.md` (the plan's Global Constraints, rulings table and calls, copied whole for every implementer) and every brief, report, review and re-review this file cites.

Abbreviations are the plan's (its line 13). CPRD, ARD, SPEC, INT and REC are `create-prd.md`, `create-ard.md`, `specify.md`, `brd-interview.md` and `brd-reconcile.md` under `plugins/product-workflows/commands/`. CLF is `plugins/product-workflows/references/coverage-ledger-format.md`. PH and NPO are `phase-handoff.md` and `next-phase-offer.md` under `plugins/workflows-core/references/`. *The slice's ledger tests* is the batch's one noun (R14) for the pair of tests §5.4 gives `/create-ard` and `/specify`. **The count.** `grep -c '^| R[0-9]' implementer-rules.md` prints 23 and `grep -c '^| P[0-9]' implementer-rules.md` prints 7: 30 rows. The plan's own tables are the same 30 rows, byte for byte: `diff <(grep '^| [RP][0-9]' implementer-rules.md) <(grep '^| [RP][0-9]' <the plan>)` prints nothing. `grep -c '^Ruling' progress.md` prints **50**: 48 lines begin `Ruling:`, and 2 begin `Ruling (to act on at resume):`, from the pause. 49 of the 50 carry a `costs:` clause; ledger line 130 carries none. **This file lists 80 entries**: the 30 rows, then the 50 ledger rulings, numbered 1 to 50 in ledger order. **The mark.** ◆ in the *Beyond* column marks a ruling that **changed behaviour beyond what the plan or the design asked**: what a run prints, names, offers or stops on, in a way neither had asked for when it was written. A ruling that only orders who fixes what, or rewords a sentence to say what the run already does, is not marked.
