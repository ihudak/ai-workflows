# Lean Context Part 1 — the Shared Loader Reads Less Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A run reads no shared reference twice, and loads the four rulebook references by part, behind a fail-closed gate — with nothing a run does, asks or writes changed.

**Architecture:** The loader skill gains a reuse rule. Four references (`escalation-rules`, `finding-triage`, `next-phase-offer`, `session-hygiene`) stay one source file each, carrying part markers; `scripts/reference-parts.py` assembles each part, with the reference's always part, its declared dependencies and a rule index, into a committed generated file under `plugins/workflows-core/reference-parts/`. A citation of a split reference names a rule, and the run loads that rule's part when it reaches the citation. The same script is the gate.

**Tech Stack:** Markdown prose executed by Claude agents; Python 3 (stdlib only) for the generator and gate; bash; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-20-lean-context-loader-design.md`. The dependency maps it argues from: `docs/superpowers/research/2026-10-20-lean-context-loader-maps/` — `whole-file-refs.md` holds every part boundary, dependency and restructure fix this plan cites by its section numbers.

## Global Constraints

- **Quality first.** No change to what any run does, asks, writes or commits. No rule may be absent at the moment it applies. Where a saving and a rule conflict, the rule wins and the saving goes.
- **Procedure references stay whole files**: `specs-repo-git`, `phase-handoff`, `cost-emission`, `addressing`, `run-flags`, `feedback-emission`, `followup-emission`, `implementation-format`, `components`, `docs-grounding`. So does `untrusted-content`.
- **No rationale or history is deleted.** A rule that sits inside a history paragraph moves into the part that needs it; the history stays.
- **One source file per reference.** Generated files are never edited by hand; each opens `<!-- generated by scripts/reference-parts.py from plugins/workflows-core/references/<name>.md — never edit; edit the source and run python3 scripts/reference-parts.py generate -->`.
- **The gate fails closed**: a malformed marker, an uncovered line, a stale generated file, an unknown part, an ambiguous rule name, or a scan that finds nothing fails.
- **The gate is its own script, `scripts/reference-parts.py`**, never a check in `scripts/check-docs.sh`, whose body is shared byte for byte with the internal editions. The internal editions are out of scope.
- **Checks 11, 16 and 20 pass unchanged in what they enforce.** Check 16 resolves a loader argument on its first token; a part name is a second token and needs nothing from it.
- **Prose is executed** (`CLAUDE.md` § Editing discipline): every moved sentence is re-read where it lands, with every pointer it carries; the claim sweep (`.claude/rules/claim-sweep.md`) runs on every rule whose place or extent changes.
- Repo rules: never name the internal organisation; no tracker name outside a `vendor-token-ok` line; requirement IDs in the `[PREFIX#N]` form; every `choices:` array 2–4 options, presented verbatim; changelog sections `— Unreleased` on the branch, dated before `main`.
- Process rules: work only in `/workspace/ai-workflows/.worktrees/lean-context-loader`; never `git checkout` in `/workspace/ai-workflows`; verify `git branch --show-current` before every commit; ask the user before `git push origin main`; ask before any Fable dispatch; during live runs, pushes and gh writes reach only `ihudak-e2e/bookstore` and `ihudak-e2e/bookstore-specs`, and the demo snapshot (`~/e2e-implement-snapshot.sh --check`) reads 18/18 `same` after every run.
- Gate chain, run as one `&&` chain, its exit code read (`CLAUDE.md` § Running the gates): `bash /tmp/claude-502/-workspace-ai-workflows/80e0a056-a775-409e-9cb9-213f6b475bf7/scratchpad/gates.sh <worktree>` extended in Task 1 with the new steps; off `main` run it without `ASSERT_PUBLISHED` while `— Unreleased` sections exist.

## Review Focus

1. **A run applies a split reference's rule from memory instead of loading its part** — the failure every map warned of. Expected: the rule's part is in the conversation before the rule is applied. Pinned by Task 12's reading of every converted call site and by Task 14's live runs, whose transcripts are checked for the part load before each applied rule.
2. **A source edited without regenerating its parts** — expected: the gate fails, naming the stale file. Pinned by Task 1's selftest case `stale_generated`.
3. **A heading renamed under a caller that cites the old name** — expected: the citation is not silently mis-placed; it counts as naming no rule (the whole reference loads) and the gate's census names it. Pinned by Task 1's selftest case `renamed_heading_reported`.
4. **A part whose assembled text lacks a rule a sentence in it relies on** — a positional pointer ("above", "below", "the next section") crossing a part boundary, or a rule kept in another part. Expected: none survive; the gate flags every positional pointer inside a part. Pinned by Task 1's selftest case `positional_flagged` and by each split task's step that lists the flags it cleared.
5. **A dependent plugin newer than its `workflows-core`** — an older loader reads `args: "escalation-rules review"` as an entry point that does not exist. Expected: `.claude/rules/plugin-updates.md` couples the versions in both directions. Pinned by Task 11's check that the coupling line names each bumped dependent.

**Interfaces:**
- Produces, used by Tasks 3–11:
  - **Declaration block**, an HTML comment directly after the source file's H1 line:
    ```
    <!-- reference-parts
    part core always
    part review needs=finding-triage/re-review
    part maintainer private
    alias review "§ Review gate" "A recorded verdict names the version it was taken against"
    -->
    ```
    `part <name> [always] [private] [needs=<part>|<other-ref>/<part>[,…]]`; exactly one `always`; `private` parts are covered but generate no file and are never requestable; `alias <part> "<name>" …` adds index names that are not headings.
  - **Regions**: `<!-- part: <name> -->` … `<!-- /part -->`. Every non-blank line after the declaration block lies in exactly one region; regions never nest; a part may own several regions, concatenated in source order.
  - **Rule index**: every heading line inside a part (its text, `#` marks dropped) plus its aliases, each mapped to that one part. Matching normalises case, strips `*`, backticks and quotes, collapses whitespace and drops trailing punctuation; two names that normalise equal in different parts are an error.
  - **Generated tree**: `plugins/workflows-core/reference-parts/<name>/index.md` (header, rule index, the part list) and `plugins/workflows-core/reference-parts/<name>/<part>.md` per non-private part: header line, `# <source title> — part <part>`, one sentence saying `${CLAUDE_PLUGIN_ROOT}` in it is workflows-core's root, the rule index, then the always part, the part and its same-file dependencies (transitively) **in source order**, then each other-file dependency under a line `Bundled from workflows-core:<ref>, part <part>:`.
  - **CLI**: `generate` (writes the tree, deletes generated files no declaration produces), `check-parts` (declarations, regions, coverage, index uniqueness, dependency resolution, freshness by regenerating in memory and comparing byte for byte; a relative markdown link in a split source fails, since a generated file sits one directory deeper — none exists today; prints positional-pointer flags as `FLAG <file>:<line>: <word>` without failing), `check-citations` (Task 7 wires it into CI): the split list in `plugins/workflows-core/skills/reference/SKILL.md` equals the declared set; every consumer file (`commands/`, `agents/`, `references/` of the four dependent plugins, `CHANGELOG.md` excluded) citing a split reference carries the preamble sentence (Task 7) as its own paragraph; every explicit `args: "<split> <token>"` names a requestable part or `index`; every citation — in the consumers and in `workflows-core`'s own `commands/`, `agents/` and `references/` — is placed: a name near it (an italic, backticked or quoted span, or a `§` reference, in the same sentence) matching one index entry places it on that part, none places it "whole"; the per-reference census `placed N, whole M` is printed, and `--verbose` lists each whole citation as `file:line`; a name that matches entries in two parts fails. `--selftest` runs every fixture case and asserts exit code **and** the message each red case must print. `--root <dir>` defaults to the repo root.
  - **Vacuity**: no declaration block anywhere, or zero citations of a declared reference across the consumers, fails.
