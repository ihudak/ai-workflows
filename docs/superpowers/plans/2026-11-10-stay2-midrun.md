# STAY-2 and MIDRUN-B4 — a stayed run's session files land on the default branch; a run typed mid-run switches nothing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A run whose preflight had to stay on a plugin branch it would have left commits its own session-file change on `<default>` without moving the checkout, and a command typed while another run of the same session is open on HEAD's branch switches nothing and commits only its own change — with D5's merged-branch hold, the record collision and D5's degraded leave fixed by the same mechanism.

**Architecture:** `session-branch.py` gains one checkout-free function, `own_change()`, that applies a run's own change — `c1` (HEAD plus the start's snapshot) to `c2` (`c1` plus the working copies) — per path onto another commit's version, by the file's class, refusing per path what only a person can settle. `specs-git.py` gains the landing primitive `land()` on top of it: the change applied onto `<default>`, `<default>` moved with `move_branch(…, here=False)` — or, where another worktree has it checked out, pushed by refspec with the local ref left alone — then lifted out of the working tree; a refused landing, or a refused path, is kept as a held commit under `refs/workflows/held/`, retried before every later preflight's guards, its per-worktree record doubling as the landing's journal. `start` records the snapshot and every stay (unkeyed, merged, mid-run) in the state record; `end` lands where HEAD still stands on the stayed branch. A run typed mid-run reads the session's other records, stays, and commits apart from the open run — on `<default>` where it stayed, on HEAD's own branch otherwise (the journalled *here* form), moving nothing under the open run. The same command typed twice parks the open record instead of replacing it, and `--started` names the record every `end` reads and writes. Every new line is worded in SRG first and pinned in `specs_git_lines.py`; `land` and `snapshot` are CLI primitives for SRG's prose fallback.

**Tech Stack:** Python 3 standard library; git ≥ 2.38 for the rest of the script, as before — the landing needs no `merge-tree` (`own_change` writes trees through a temporary index); the gate chain of `.github/workflows/validate-catalog.yml`.

**Spec:** `docs/superpowers/specs/2026-11-10-stay2-midrun-design.md` (binding; the maintainer's decisions S1–S4 are settled; its mechanism revised after this plan's review and re-review by the controller's rulings, as its Status lines record), with its research memo `docs/superpowers/specs/2026-11-10-stay2-midrun-research.md` (evidence; the design wins where they differ). ## The maintainer's decisions (2026-11-10)

Quoted from the spec, §2; not reopened here.

- **S1** — A run whose preflight stayed on a plugin branch it would otherwise have left commits **its own** session-file change on `<default>` in the same run, **without moving the checkout**, and pushes it where §4 step 5 allows. It then takes that change out of the working tree on the stayed branch. Files already dirty when the run started are not its own and stay where they are.
- **S2** — D5's merged-branch hold is replaced by the same landing: one rule for a merged stay and an other-key stay. PR #182 merges with D5 as shipped.

The outer run's protection ends when its command runs again, when HEAD leaves the branch, at `/clear`, at its `end`, or after 7 days.

## Global Constraints

Carried from 2a, re-derived for this batch:

- Python 3 standard library only. One JSON object on stdout per call; exit 0 when it ran; exit 2 with exactly one `specs-git: not run (<reason>)` line on stderr, never a traceback.
- **`--specs <root>` is the repository's top level** for every subcommand but `start`, `end` and `specs-root-check` — `land` and `snapshot` included — as `session-branch.py` checks (`rev-parse --show-toplevel`, by `realpath`).
- **Exit 2 only before the first write.** `start`, `end`, `replay` and `declined` keep 2a's boundaries. `land` exits 2 only before its first write — the held record's journal write, which comes before any ref is moved or pushed, or a held ref's write or removal; `snapshot` only before it prints. Objects written before that (`hash-object -w`, `commit-tree`) do not count, as `sb.commit`'s own `commit-tree` before its `update-ref` does not. After it, every outcome is exit-0 JSON with `error` set where an exception stopped it.
- **Bounded calls.** Every `fetch`, `pull`, `push` and `ls-remote` runs through `sb.git_bounded` with 2a's caps (60 s, `ls-remote` 30 s). The landing's pushes ride `push()`, which is bounded, its refspec form included. `start`'s budget is checked before each held entry's capped calls and before `<default>`'s push, as before any capped call (P28).

Tests: Task 7 `t_midrun_abandoned`, `t_midrun_ends_*`.

## Rulings this plan takes

The planner's calls where the spec or the controller's rulings left a choice open; each one's cost if wrong is what the final report names. P2, P5, P6, P7, P19, P22, P25, P26, P27 and P34–P36 carry the controller's rulings in this plan's words.

- **P1 — the noun.** SRG §7 already says "a nested run" for a run another command starts (`/brd-split`'s *Ground now*). The new case is **a run typed mid-run**, and the run it finds is **the open run**; its stay's kind is `mid-run`, and the code's names are `midrun`.
- **P2 — the here form (ruling M1; the re-review's journal ruling; the final check's F2, F6).** A run typed mid-run on a branch it would not leave — HEAD on `<default>` (B1), on a branch a key of the run names (B3), or on a non-plugin branch under G2 — commits its own change **on HEAD's branch**: `own_change` onto HEAD, HEAD's branch moved by `update-ref`, then `restore --staged` of exactly the landed paths; no file written. Journalled twice before the ref move: in the held record (`land` writes it for every form, the CLI's included; its `onto` and `branch` are HEAD's branch), and, under `end`, in the state record's `end_commit.here`. `symbolic-ref -q HEAD` and the `index.lock` are rechecked immediately before each step. A here journal is finished — by `end --resume` or the next preflight's held stage — only where the move is verified: with HEAD's branch at the journalled tip and HEAD naming it, the restore step, from the journalled `index_before`; with it still at the journalled `old`, the here form again from the entry's `c1`/`c2`; otherwise the entry is dropped and the files are left as they stand. Outside session-branch mode only. A refused here form commits nothing and holds nothing, refused whole (the *mid-run* row): a held entry is landed on `<default>` by the held stage, the wrong place for a B3 or G2 branch's files, and the open run's own `end` takes them; the spec's §3.3 says so.
- **P3 — one attribution rule for every stay.** S1 and S2 bind: a merged stay subtracts its snapshot too.
- **P4 — the same command typed twice at its start is not a run typed mid-run.** Spec §3.3 tests "another command's record", and S3 ends the protection "when its command runs again". D-park only keeps the first run's record.
- **P5 — `end` with no start (ruling N3).** On the record kinds `missing`, `ignored` (`--no-preflight`) and `declined-only`, `end` runs the open-run test, once its gate passes and HEAD is a branch, before any pull or commit, over every record of the session `_open_run` passes save the one `--started` names — this command's own others included, since with no snapshot no file can be told apart — and, where one is open on HEAD's branch, writes nothing: no catch-up, no commit, no record saved; it prints `row.midrun-kept` with `reason.land.no-preflight`. This replaces the first version's parking in `--no-preflight`. It reads S3's "when its command runs again" as "when its command's start runs again": a same-command run that stops before its start leaves the first run's protection standing, and SRG §3.5 says so (P33 matches it by hand).
- **P6 — the journals (the final check's F2).** The held record journals every landing: `land` writes the entry, with the tip it built and the `old` it moves from, before `<default>` (or HEAD's branch) moves or is pushed, and removes it once the lift (or the restore) is done. A journal entry is finished only where the move is verified: a landing journal is lifted only where `<default>` holds its tip (or, for a remote-path entry, `origin/<default>` after a fetch); where `<default>` still stands at its `old`, or holds neither, it is landed again as a held entry — never lifted unverified, since a lift there would write `c1` back over a change that is nowhere else. A here journal, as P2. The next preflight finishes what a kill left where no resume comes.
- **P7 — held commits chain only on a shared path (ruling M2), and the lift's target.** `land` and the held stage hold a change behind an earlier entry only where both touch a path and that entry's cause is transient. After landing, a path is lifted to the oldest landed entry's `c1` version where its working copy is the newest landed entry's `c2` version — across `retry_held`'s chain and across the held entries `land` lands before its own change.
- **P8 — a held file changed since it was held** — edited, committed, removed or restored — leaves the entry: the held commit is rebuilt without it (`held_rebuild`); an entry left with no file is dropped. Where the file is still dirty, the flush, or `end`'s commit, commits it where HEAD stands and prints `pre.held.changed`.
- **P9 — where held entries are dropped instead of landed.** With HEAD on the default branch — at the held stage and at `end` — and in session-branch mode, each entry is dropped with its ref, its files left to the flush, `end`'s commit or §8.2's `commit`; a here-form journal entry is finished, never dropped. Under `specs_git: misrooted`, on a detached HEAD or where the gate did not pass, nothing is done.
- **P10 — the CLI.** `land --branch <b> --default-ref <r> --command /<name> [--commit-key K] [--snapshot <file> | --snapshot -] [--register-rebuild P] [--here]`; `land --default-ref <r> --retry-held`; `land --default-ref <r> --drop-held <sha7>`; `snapshot`.
- **P11 — the snapshot's lifetime.** Taken right after a fresh, non-re-run start's first save, with `<default>` resolved without a fetch and `sb.mode` read there, where the gate passed, no misrooted flag stands and the mode is not on (its blobs written with `hash-object -w`); updated by the held stage for each path it lifts — the lifted version's blob, or the path removed where the lift made it clean (re-review m2); narrowed at every call's return (`_close`) to the paths still dirty, each otherwise keeping its blob; a `--rerun` carries its first start's and only narrows it.
- **P12 — `merged_stay` becomes `stay`**, `{branch, kind, reason, merged, command}`. `state.load` maps a 1.82.0 record's `merged_stay` to a stay of kind and flag `merged`. The unlisted clause is keyed on `pre.status-failed` in the record's `reported`; a record with no snapshot for another cause lands against HEAD with no clause — a cost SRG states.
- **P13 — the open-run test** is spec §3.3's, plus: the record's `top` equals this run's; its `started` is within 7 days (S3); it does not carry `protects: false`; and its start set no `specs_git` (P34). Parked records are read like any other; at `start`, this command's own files never are (P4).
- **P14 — one stay line.** Where more than one reason to stay holds, §3.5 prints one: the misrooted line, else the unlisted one, else the mid-run one.
- **P15 — the landing's own reason clauses** (re-review m10; the final check's F1, F12). `reason.land.dropped` (a `follow-ups.md` line `<onto>` lacks, dropped), `.edited` (a block entry changed or removed), `.forms`, `.deleted`, `.folder-gone` and `.register` for `own_change`'s refusals; `.moved` for a move refused twice (a `branch-moved` or `checkout-moved` refusal is retried once on the new tip); `.checked-out` with the refspec push's outcome; `.no-preflight` for P5. `reason.locked` is reused as it stands, since it names no replay. `<onto>` is `<default>`, or HEAD's branch in the here form.
- **P16 — where the code lives.** `own_change` and `move_branch`'s `message` in `session-branch.py` (ruling C1); the landing, the held record and the CLI in `specs-git.py`.
- **P17 — the unsupported clause** applies to a landing's row (its `<branch>` is `<default>`) and to `row.here`, not to the held, *mid-run* or *there* rows.
- **P18 — two sessions on one checkout** — "Not covered, stated" — in SRG §3.5 and `to-fix.md`'s *Accepted* section (MIDRUN-2S).
- **P19 — the run's identity (ruling N1; the final check's N1 remainder).** `start`'s JSON gains `started`; the skill passes the last start's as `end --started` and `declined --started`, and `replay` takes it too; `end`, its replay and `declined` resolve the record with `state.find` and carry its path as `run["record_path"]`, which **every** save and the removal in `_end` and its callees write — `boundary`, `about_to_commit`, the commit's save, the `--resume` save of a found commit, the `on_move` saves of `end_commit.landing` (Task 5) and `end_commit.here` (Task 7), `_end_session`'s three, `_push_step`'s `end-replay` save, `_replay_end`'s, `finish_end`'s and `_stop`'s removal — and `declined`'s save. Without `--started` (an older call, the prose), `<command>.json`, as 2a. A `--started` that names no record: P35.
- **P20 — what a run typed mid-run moves** (re-review m3; the final check's F4). Nothing under the open run while it stands: no catch-up and no retry of HEAD's push at its start, no catch-up at its end, and the here-form commit not pushed — `row.here` says the next push of that branch this plugin makes carries it, as a push publishes every session-file commit on the branch. `end` re-tests the open run first (P36). The landing on `<default>` from a mid-run stay moves nothing under the open run, and pushes as any landing.
- **P21 — the default branch's push lives before the guards.** The held stage pushes `<default>` where HEAD is not on it and step 5 allows; the settle loop's list is unchanged. A rejection names `replay --for start --branch <default>` at once, whose `next` resumes at the guards.
- **P22 — stuck held paths (ruling M2; re-review m6; the final check's m6 remainder).** Permanent: `own_change`'s refusals, and a remote path with no `origin`, a push configured to another remote, or `origin` lacking `<default>`. Transient: a refspec push that failed, and one `origin` refused — or a refusal already recorded (`push_check`'s `refused-before`) — since the refusal record turns session-branch mode on from the next run, where P9 drops the entry for §8.2's `commit`; `reason.land.checked-out` names each. `pre.held.stuck` every run, and `row.held-stuck` or `app.held.stuck` at the end, name the commands to see the change and to drop the hold (`land --drop-held`), after which the files are ordinary uncommitted files.
- **P23 — M6's pin** lives in `specs-git.py`'s selftest (`k_branch_check_midrun`): `check-branch-check` reads which commands request `branch-check`, not the stop's wording.
- **P24 — the prose's snapshot.** `specs-git.py snapshot` prints it; the prose keeps it in its conversation and passes it back on stdin (`--snapshot -`).
- **P25 — the guards' forms under a run typed mid-run (ruling N2; the final check's F5, F8).** A run typed mid-run takes the mid-run form whatever its stay's kind and flag. G1: *Not done* `g1.landing.not_done` (alternative 2) where it stayed, else the plain block's; an empty *Fix* (§5's rule for a block with nothing to run); *If ignored* `g1.midrun.if_ignored`. G2, every variant: an empty *Fix* — none names a switch while the open run stands on the branch — and *If ignored* `g2.midrun.if_ignored`. The block `end` repeats is rendered the same way from the plain block the record keeps. Otherwise the kind decides G1's *Not done* alternative and the `merged` flag its *Fix* and *If ignored*.
- **P26 — a change already there (ruling).** Where `own_change`'s tree equals `onto`'s and nothing was refused, `land` returns `there`: nothing committed, the lift still made; `end` prints `row.there`. In the here form `there` means nothing of the run's is dirty: `row.nothing`.
- **P27 — the drop rule (ruling N4; the final check's F1).** A change that drops what `<default>` lacks, or rewrites an entry, is refused, permanent — its two halves: a block-shaped file whenever any entry of `c1` is missing from `c2`, whoever holds it (`edited`); `follow-ups.md` where a line of `c1` that `onto` lacks is missing from `c2` (`dropped`). A line `onto` holds, edited in place, lands as a second copy beside it (`followup-emission`'s two-copies case); a line `onto` holds and the run dropped stays on `onto`, the lift returning it to the working copy. Nothing of the branch's own content reaches `<default>` ahead of its pull request.
- **P28 — budgets for the retries** (re-review m5). `retry_held` takes a `check(cost)` callback, called before each entry's capped calls; the held stage passes `start`'s budget, which stops at `held` and resumes there. At `end`, which has no budget, held entries are retried locally only: an entry that would need the remote path stays for the preflight, and a change on a shared path is held behind it.
- **P29 — per-path refusals** (re-review m7; the final check's F10). `own_change` applies every path it accepts and lists the refused ones; `land` commits the accepted, holds the refused paths alone as one permanent entry, and lifts only the landed paths; the row is the landed commit's with `app.held.stuck`, or `row.held-stuck` where nothing else landed. Where the accepted paths' tree equals `onto`'s (they were already there) and some path was refused: no commit, the accepted paths lifted, the refused held, `row.held-stuck`. A `register-rebuild` refusal refuses every path of that `security/<slug>/`.
- **P30 — G1's *Not done* opening** (re-review m1). "the preflight did not switch branches, and committed and pushed nothing on the branch you stand on" in the plain block, "… on `<branch>`" in the landing form: true where the held stage has just committed and pushed `<default>`.
- **P31 — orphaned held refs** (re-review n3). The held stage removes each `refs/workflows/held/*` ref no live worktree's held record lists (`git worktree list --porcelain -z`, each worktree's `rev-parse --git-path workflows/held.json`).
- **P32 — the landing's reflog** (re-review n4). `sb.move_branch(…, message=None)` and `ref_transaction(…, message=None)` take the reflog message, the replay's unchanged by default; the landing passes `specs-git: landed <sha7>`.
- **P33 — the by-hand trigger's end** (re-review m16; the final check's F15). By hand, another command counts as open only until its preflight prints its `Environment:` line again in this conversation — its start running again, as P5 reads S3 — or HEAD leaves its branch, the two of S3's ends a prose run can observe.
- **P34 — a run whose start set `specs_git` protects nothing** (the final check's F3). A misrooted or blocked run commits nothing at its end, and a misrooted one's files lie under a path the run found wrong, so `_open_run` skips its record. 2a's `e_stale_no_preflight`, whose seeded record carries `specs_git: misrooted`, then passes unchanged, keeping its intent: a stale record never decides a later run's commit.
- **P35 — a `--started` that names no record** (the final check's F7). `state.find` matches `<name>.json` whose `started` is the stamp, else the file `<name>.<stamp>.json` by name. Where neither exists — a third start replaced a restored record — `end`, its replay and `declined` take the run's own derived path, `<name>.<stamp>.json`, never `<command>.json`: `declined` creates its record there, and `end` takes kind `missing` (or `declined-only`) and saves and removes there; P5's test then sees the other run's open record. Nothing is refused, so the run's end still runs.
- **P36 — the end re-tests the open run** (the final check's F4). `end`, where `rec["midrun"]` is set, resolves it with `state.find(session, midrun.command, midrun.started)` and `_open_run`; where it no longer stands (its `end` ran, HEAD left, it was replaced), the here form still commits only the run's own change, then pushes it as step 5 allows and prints the row that commit's push takes, with no mid-run wording; a mid-run stay lands as always, its `app.landed` alternative worded for the start ("was open when this run started").

## Out of scope

- **Inheriting the open run's keys** — rejected (S3).
- **A `declined` call from a second run of one command before that run's start** — unreachable: a run reaches its handoff only after its start.
