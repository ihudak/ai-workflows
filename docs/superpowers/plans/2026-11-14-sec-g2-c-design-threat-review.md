### `## Threat review` — the shape (Task 3 writes it into `design-format`; every later task consumes it)

````markdown
## Threat review

- **Models read:** [[<KEY>]] threat-model.md[, [[<KEY>]] threat-model.md]

### [DT#1]: <title>

- **Answers:** [[<KEY>]] [TH#N] | —
- **Where:** <component id>[, <component id>…][; contract <pair>]; interface <its label in ## Interfaces / contracts | —>
- **Threat:** attacker: <who>; action: <what they do>; asset: <what is at stake> | as [[<KEY>]] [TH#N]
- **CWE:** [CWE-<n>](https://cwe.mitre.org/data/definitions/<n>.html) | —
- **Disposition:** <exactly one of the three forms below>
- **Test:** <the opening words of the ## Test strategy line that checks the Rule>[ — <the specification test case's id, where one exists>] | —
- **Withdrawn:** <why>                     (a withdrawn entry only)
````

- **The section is optional**, the fifteenth, after `## Pieces`: present only where a review ran or an earlier one's section is kept, and left out with no `_N/A_` line. No section number moves.
- **`Models read`** names each model the review read, by its folder's key in the wikilink form. `<KEY>` is the run's own `<EPIC>` or `<PRD>` key for that folder, never one parsed out of the file.
- **The six fields** are list items in that order, each present once on every entry. `—` marks an empty Answers, interface, CWE or Test.
- **An entry answering a model's threat** has `Answers: [[<KEY>]] [TH#N]`, a title of its own (Task 3's review: never the model threat's title), and `Threat: as [[<KEY>]] [TH#N]` — it cites the model's threat and copies none of its text, title included. **A new threat** has `Answers: —` and a full Threat line.
- **Disposition** holds exactly one of:
  1. `Mitigated — Rule: <testable statement>`
  2. `Not this design's — answered in [[<KEY>]] design.md`, or `Not this design's — the interface it attacks is not built by this design: <which is>`, or `Not this design's — does not arise: <why>`
  3. `Returned to the architect — <why the design cannot answer it>`
- **Test** is not `—` on a live `Mitigated` entry, and is `—` on every other.
- **A live entry** carries no `- **Withdrawn:**` list item at the start of a line.
- **Never a `- [ ]` line** in the section: Phase 7 refuses a `design.md` holding one.
- **Across folders**, D names an entry `[[<KEY>]] design.md [DT#N]`.
- **Identity** (D4, in format §5's words): an entry is bound once it stands on the specs repository's default branch; where that branch holds no copy of the design, every entry the folder's file holds is bound. A bound entry is never renumbered or deleted. `[DT#N]` is numbered per `design.md` from `[DT#1]`, contiguous over live and withdrawn entries. A reworded Rule keeps its id. A changed Where or Threat is a new `[DT#M]`, the old one gaining `- **Withdrawn:** superseded by [DT#M] — <why>`.

### The `design-threat-modeler` brief and reply (Task 4 writes the agent; Task 8 dispatches it)

**The brief** has twelve fields, every one present, `none` where empty. Each label starts at column one. A field's first item follows its label on the same line; each further item sits on its own line, indented two spaces.

```text
Review this design's threats.

Scope: prd | epic
Target: <the Epic's target: id> | none
Component set: <one line per id: `<id> — <kind> — <paths>`>
Contracts: <one line per row: `<pair> | <producer> -> <consumers> | <kind> | <status>`> | none
Interfaces: <one line per settled interface: `<n>. <label> — boundary: <yes|no> — <its boundary behaviour>`> | none
Deferred threats: <one line each: `[[<KEY>]] [TH#N] <title> — Where: <…> — Threat: <…> — CWE: <…> — Deferred: <what the design must answer>`> | none
Context threats: <one line each: `[[<KEY>]] [TH#N] <title> — Where: <…> — <mitigated|accepted>: <its Disposition>`> | none
Code scan: <per repository: `<repo>: <file:line> — <what is there>`> | none
Weakness classes: <one line per class: `<repo> <cwe> <cwe_url> live=<n> top=<severity> in_component=<true|false> recurs=<true|false> answered_in_grill=<true|false>`> | none
Held entries: <a revision: one line per live held entry: `[DT#N] <title> — Answers: <…> — Where: <…> — Disposition: <…>`> | none
Rule bar: <design-format.md sections 4 and 8, verbatim>
Cap: 15
```

- **Contracts** are the Phase 2.5 `contracts` rows, each as its pair `[[<PRD-KEY>]] ard.md [AD#N]` on an Epic, `ard.md [AD#N]` on a PRD-level design; on an Epic with a target, only rows whose producer or consumers name the target.
- **Interfaces** are numbered by the run from `_design-session.md`'s settled interface decisions, in the order they were settled. The label is the run's own text.
- **Weakness classes** come only from the JSON whose path Phase 4's existing `workflows-core:weakness-classes` call printed: each class's `repo`, `cwe`, `cwe_url`, `live`, `top_severity`, `in_component` and `recurs`, and no other field. `answered_in_grill` is `true` where the grill recorded a `Known weakness:` line for that CWE in that repository. Where the run holds no class, or the file can no longer be read as a JSON object whose `classes` is a list, the field reads `none`, and in the second case the report carries `threat review: weakness classes not passed — the JSON file the skill named could not be read`.
- **Rule bar** is copied from `${CLAUDE_PLUGIN_ROOT}/references/design-format.md`: item 4 (`## Interfaces / contracts`) and item 8 (`## Test strategy`) of *Sections (in order)*, one item per non-blank line, read again from the file where the run no longer holds the text. No copy is kept in the agent.

**The reply** — exactly this YAML, then any `Untrusted-content notice:` lines:

```yaml
status: OK | EMPTY | ERROR
error: <one line; ERROR only>
overflow: "<n> more: <title>; <title>; …" | none
answers:                         # one per line of Deferred threats, in its order
  - answers: "[[<KEY>]] [TH#N]"
    where: { components: [<id>, …], contract: <pair> | null, interface: <number> | null }
    proposed: mitigated | returned
    rule: <a testable statement> | null
    lands_in: <what the design's interface, error-handling and test sections gain> | null
    test: <the test that checks the rule> | null
    return_reason: <why the design cannot answer it>
candidates:                      # at most 15 new threats, ranked
  - rank: 1
    title: <short title>
    where: { components: [<id>, …], contract: <pair> | null, interface: <number> | null }
    threat: { attacker: <who>, action: <what they do>, asset: <what is at stake> }
    cwe: CWE-<n> | null
    proposed: mitigated | returned
    rule: <a testable statement> | null
    lands_in: <…> | null
    test: <…> | null
    return_reason: <why the design cannot answer it>
```

- `rule`, `lands_in` and `test` are set only where `proposed: mitigated`. `return_reason` is always set, so *Return it to the architect* can offer a reason.
- **Ranking** (D5): candidates on a boundary interface first, then those whose `cwe` is a class in *Weakness classes*, then the rest. The cap is 15.
- `EMPTY` means no deferred threat and no candidate. `ERROR` means the brief cannot be read as the contract gives it.
