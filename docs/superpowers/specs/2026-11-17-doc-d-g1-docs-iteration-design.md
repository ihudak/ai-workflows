## Intent

`/docs-audit` writes a ranked backlog of documentation units and nothing turns a unit into a page: route steps 4 to 6 — write, capture, verify — are procedures a person follows (ROUTE:87-194), each ending in a *Later: … No such command exists yet* line (:115, :157, :194). The shipped references were written ahead of these commands and still name them as future writers: BF:102-103's lifecycle rows, FG:108's "no automated writer" of `unit:`, EC:99 and :105 on walkthroughs and the checklist, and ST:5 and :464 on regenerating the navigation, which ST:466 and ROUTE:104 do by hand meanwhile — the interim fix of DOC-C-B1 that `docs/superpowers/reviews/2026-10-26-fix-batches.md:482` says this track replaces.

This design adds `/docs-write` (draft a unit's page), `/docs-verify` (resolve its claims) and `/docs-capture` (record a process first). It settles what the three share and specifies `/docs-write` in full; the other two get their contracts here and the rest in their own design-questions step (D1). **One noun:** *a backlog run* is a run of any of the three — it reads the backlog, works units, and moves each unit it finishes.

## What exists today

- **The lifecycle has one writer.** BF:99-107 names a writer per edge; today `/docs-audit` writes them all — `missing` at mint, and on a `--refresh` `missing → drafted` or `missing → published` for a page found carrying the unit's `unit:` id, by whether that page holds a marker (AUD:224, BF:109-116). BF:122 rests the publish edge on "a person wrote that page, wrote that id onto it". `captured` is the sixth value BF:97 left out, under its rule that a reader treats an unrecognised status as a later spec's and leaves the unit alone.
- **`/document` cannot take a unit.** Keyed mode needs a PRD folder and diffs (DOC:16, :64-140) and files its pull-request draft there (FH:93); direct mode is held to no review and "no branch and no commit, ever" (`.claude/rules/docs-workflows.md:54`, :56).
- **Its agents are PRD-shaped.** `doc-writer` takes `folder_read`, `diff_summaries` and a planner checklist (`agents/doc-writer.md:14-26`); `doc-reviewer` refuses without the checklist and diff summaries (`agents/doc-reviewer.md:34`), grades six dimensions from the planner (:47-49, :53-57), reads `/document`'s gate registry (:60), returns a fixed shape (:67) and may "NEVER invent new review dimensions" (:150); `doc-fixer` refuses any input that is not a reviewer's or a style checker's output (`plugins/workflows-core/agents/doc-fixer.md:26`). `doc-location-finder` is generic (`agents/doc-location-finder.md:14-20`).
- **The specs repository admits** for a documentation run `documentation/*/dev-workflows/**` and nothing else (SRG:115, :128).

## Goals, non-goals, anti-goals

**Goals.** (1) Route step 4 runs as `/docs-write`: a reviewed page on a branch, with its navigation, its unit moved `missing → drafted` in the same commit. (2) Step 6 as `/docs-verify`, `drafted → verified` only where nothing is unresolved. (3) Step 5 as `/docs-capture`, `missing → captured`. (4) The coverage grid moves only on evidence. (5) No existing command changes behaviour beyond the false MAJOR D9 removes. (6) A minimal GIT-G1 footprint, every edit named.

**Non-goals.** `/docs-drift` (DOC-D-G2) and every `stale` edge; a browser driver (EC:127); `verified → published` (BF:118); `release` units, the What's-new pages (D14); any change to `/document`'s command file; a `schema_version` bump; a backlog in the specs repository; a pull request opened by the plugin in a docs repository (FH:8).

**Anti-goals.** A unit moved, or a page tagged with its id, by a run that did not finish it (D8). A command certifying its own prose. A user-audience claim resolved by a code read, or an engineering one by observation (EC:135). A second prose copy of `/document`'s chain (D4). A backlog, walkthrough, profile, capture or ref value reaching a path, a ref or a shell without a set or a class (D13) — **the one named exception** is the profile's build and lint commands, which are executed configuration, as `/document` runs them (`references/docs-profiles/docs-profile-schema.md:122`), shown to the operator verbatim in this run's consent before they run (D5). Any write into a source repository, or any deliverable, deliverable branch or branch prefix in `$SPECS_PATH`.

## Decisions

### D1. Three sub-projects, one contract

This design settles every rule crossing the three commands and builds in three sub-projects, each with its own plan, reviews and release (question 1): **(1) `/docs-write`** with `<unit-id>`, `--next` and `--batch <n>` — usable alone, its units resting at `drafted` until step 6, by hand meanwhile; done when a `--next` run commits a page, its navigation and its unit's move in one commit and the strict public build passes over it. **(2) `/docs-verify`**, both backends, which closes the loop the grid measures. **(3) `/docs-capture`** and `captured` — last, because a code-first how-to still reaches `verified` through `/docs-verify`'s composed walkthrough, so capture improves process-shaped pages and blocks nothing. Family D22 put capture first; that is right for a how-to's quality and wrong for shipping. Each sub-project opens with a design-questions step (*What is left to the builder*), as P3 §5's batches do. Rejected: designing `/docs-write` alone — the state machine and the git discipline bind all three.

### D2. Where each artifact lives

| Artifact | Where | Git authority |
|---|---|---|
| Backlog, walkthroughs | `<top>/.dev-workflows/docs-backlog.yml`, `…/walkthroughs/<id>.yml` (BF:154, EC:97) | the docs-repo finish (D10) |
| Pages; `in-repo` images | the profile's content root in the docs repository `resolve-docs-repo` answers (D3) | same |
| Cost and feedback | `$SPECS_PATH/documentation/<docs-repo-slug>/dev-workflows/` (SRG:115) | `specs-repo-git`, through the `specs-git` skill's `start` and `end` |

The backlog stays in the docs repository (family D5). Pages reach `$DOCS_PATH` only where `resolve-docs-repo`'s rung 3 answers there (RR:28), a write-target rung, not grounding (D14). **No `phase-handoff` register row changes and no producer, `require-on-main` consumer, `branch-check` caller or branch prefix is added**: the register classifies the specs deliverables `deliverable_paths` declare (PH:406), these commands declare none, and `phase-handoff` runs only `git -C "$SPECS_PATH"`.

### D3. The target

- **The selector never reaches the ladder.** RR's rung 1 takes "the first positional token … as given" (RR:26), so a unit id there would resolve as a directory (AUD:30's failure). The docs repository is named by `--docs-repo <path>`, handed to `resolve-docs-repo` as its rung-1 token; with no flag the ladder starts at rung 2.
- **The target is a git work tree's top level**, tested before the start call. A directory outside every work tree is no target for a run that commits, so the stop is a refusal before the target is resolved and takes no tail. **The run declines its tail by its own statement**, as SRG §4 lets a command state (SRG:757-761); that permission's stated reason, an entry left waiting in pending, does not reach this case, whose entry would have a home (SRG:132's basename). Declining it keeps SRG:132's "three runs' command bodies lead to that last case" true. Rejected: taking the tail, a fourth run behind SRG:132 and a GIT-G1 edit for a run that did nothing.
- The other pre-target stops (an unknown flag, a bad `--batch` value, a run-flag stop, the ladder's Cancel) take no tail, as AUD:30 and :32's do; every stop after the target takes AUD's stop route (AUD:18).

### D4. `/docs-write` against `/document`: own phases, the same agents, one reference for the difference

- **Delegation is rejected.** No mode of `/document` takes a unit, a third mode changes `/document`, and one command starting another while its own record is open is what P3 rules out (P3:24, :79), short of an `--inline` start-skipping exception (`plugins/workflows-core/skills/specs-git/SKILL.md:10`).
- **Extracting a shared reference from `/document` is rejected for now**: 328,791 bytes interleaving the PRD read, the discrepancy escalation and the CDN handoff, a regression risk for a benefit the agents already give.
- **Own phases dispatching the same agents** — `code-scanner`, `doc-location-finder`, `doc-writer`, `docs-style-checker`, `doc-fixer`, `doc-reviewer` — and citing the same references: `toolchain-preflight`, `gate-ledger` (§7's adoption, `references/gate-ledger.md:159-163`), `render-verification`'s build check, `repo-verification-gates` applied by the orchestrator as direct mode does, `workflows-core:finding-triage` (`/docs-write` takes its `doc-reviewer → doc-fixer` attachment row, `finding-triage.md:36`, with `/document`'s re-review rules), `workflows-core:escalation-rules`.
- **The difference lives in `references/docs-iteration/unit-brief.md`, and its list of replaced sections lives there once.** The file opens with that list, by heading. Each of `doc-writer` and `doc-reviewer` gains one sentence that only points there: with `brief_kind: unit`, read that file; what it names, it replaces; everything else stands. The agent files never restate the list, and `docs-workflows-backlog.md` carries the invariant that an edit to either agent's inputs, steps or dimension table re-reads that list in the same change. A brief without the field — every `/document` dispatch — reads today's text. The list, as the file will open:
  - **`doc-writer`**: *Inputs* (:11-26), *Entry validation* (:29-36), and *Write mechanics* steps 2 (a new page only, so `published` and no changelog), 4 (no planner snippets), 5 (no screenshot policy: slot placeholders, D9) and 7 (no discrepancy decisions: markers, D9) (:47-65). Steps 1, 3, 6, 8 and 9, the anchor rule and *Output* stand. **A second input, `answers`**, makes `doc-writer` the applier of `/docs-verify`'s recorded answers (D11).
  - **`doc-reviewer`**: *Inputs* and its refusal (:16-34); *Review method* step 2 (:39) — claims cross-checked against the unit's evidence and the source repositories, not a PRD and diffs; the rows **Factual correctness** (graded against the evidence, an unmarked claim with none behind it a BLOCKER, the page-level marker required — D9), **Completeness vs plan** and **Coverage** (graded against the unit's type, not a checklist), **YAML frontmatter** (also the three reserved keys the writer sets, `evidence:` entries with their `ref`, `review_by`, the internal marker on an internal page, and BF §7's visibility-path pair), **Repo authoring guidance** and **Repo verification gates** (read from the brief's fields, which the orchestrator extracts), **Screenshots** and **Snippets** (`N/A — unit brief`, save slot placeholders under Screenshots), **Verification-gate integrity** (read against `/docs-write`'s registry, which `gate-ledger.md` gains as a section of its own beside §4, `/document`'s, as §7 says an adopter declares its own table); the hard rule at :151 (a planner topic missing); and the *Recommended next step* lines, which name `/docs-write`'s phases. **No dimension is added**: :150 and the output shape (:67) stand, every heading present.
- **`doc-location-finder`, `docs-style-checker`, `doc-fixer` and `code-scanner` are unchanged.** `doc-planner` is not used. Rejected: two new agents, which would copy the frontmatter, snippet, anchor, traceability and untrusted-content rules and drift.

### D5. `/docs-write`'s phases

Signature: `/docs-write <unit-id>|--next|--batch <n> [--docs-repo <path>] [--skip-costs] [--skip-feedback] [--enforce-model=<model>]`.

- **Phase 0 — Resolve.** Strip the run flags; load `escalation-rules core` before the start call (P3 §4.3, :81); parse exactly one selector; resolve the target (D3); test `<top>` writable; `specs-preflight`, keyless (D13); read the profile (absent or unreadable: a stop naming `/docs-workflows:docs-profile`); read the backlog — absent, an unknown `schema_version` (BF:65), not committed (D10), outside the shape D13's line reader accepts (naming the line), or an id held by two entries: a stop before any write; where `<top>/.dev-workflows/unfinished/` is not empty, one line naming each unit directory in it (D8); the toolchain preflight against the profile.
- **Phase 1 — Select and resolve sources.** Select on the backlog as read (D7); then sort each selected unit's evidence into artifact entries and code entries and resolve each (D13, D14) — before any consent, so the consent shows what the run will read. MODERATE per unit (family §12.1); `doc-writer` on its Opus chain, `doc-reviewer` on its Opus pin (family D20).
- **Phase 2 — Ground.** Read each artifact entry by D14. One `code-scanner` per resolved clone — never `$SPECS_PATH` or a path inside it (D13) — in a single response, capped at four, `capability_themes` the unit's title and its surface's title, `context` composed from its type and audience, `search_hints.paths` its evidence paths (the agent refuses without themes and a context, `plugins/workflows-core/agents/code-scanner.md:40`), refreshed by `workflows-core:scan-refresh`'s fixed policy as AUD Phase 2 is; each `prep.scanned_ref` resolved to its commit (BF:89).
- **Phase 3 — Place.** `doc-location-finder`; only a new page is legal (one unit, one page, CM:83). A `missing` unit whose `page_path` is set uses that path where it passes D13's class and names no existing file, else stops naming `/docs-audit --refresh`. BF §7's visibility-path pair holds. **Consent** — single: `["Write it (Recommended)", "Enter another path (you'll be prompted)", "Cancel"]`; batch: once (D7) — over the unit, each source clone's path, each artifact's path, the page path, the branch, every ref D7 could not read, and, verbatim, every profile command the run will execute.
- **Phase 4 — Branch** (D10), then **re-read the backlog** on the branch the run now stands on and re-resolve the unit — same id, same status, `blocked_by` still empty — stopping before any write where any differs; a batch drops each unit that fails and names it, the rest being a subset of what was consented.
- **Phase 5 — Write.** `doc-writer`, `brief_kind: unit`. The page carries no `unit:` key yet (D8).
- **Phase 6 — Style.** `docs-style-checker`, then `doc-fixer` on its violations, untriaged, as in `/document`.
- **Phase 7 — Navigation and build.** Regenerate the navigation (D9); run every `builds[]` command, gating, each a ledger row.
- **Phase 8 — Review.** `doc-reviewer` at Opus, `brief_kind: unit`; triage; `doc-fixer` on survivors; one fix cycle and one re-review; an unresolved BLOCK escalated as DOC Phase 7 does. An edit after Phase 7 re-runs Phase 7.
- **Phase 9 — Commit the unit** (D8). **Phase 10 — Finish** (D10), once per run. **Phase 11 — Report**, then AUD's emitter tail, `commit-artifacts` last.

`--batch` selects and resolves every unit's sources (Phase 1), places every unit (Phase 3), asks once, and branches once (Phase 4), then runs Phase 4's re-check and Phases 2 and 5 to 9 per unit.

### D6. The state machine

| From | To | Written by | In the commit of |
|---|---|---|---|
| `missing` | `captured` | **`/docs-capture`** (sub-project 3) | the walkthrough, its `in-repo` images |
| `missing` | `drafted` | **`/docs-write`**; `/docs-audit --refresh` (unchanged) | the page, its `unit:` key, its navigation |
| `captured` | `drafted` | **`/docs-write`** (from sub-project 3) | same, prose from the walkthrough |
| `drafted` | `verified` | **`/docs-verify`** | the resolved page, the walk's results |

Every other edge in BF:99-107 is unchanged; the `stale` edges stay with the drift track. `captured` joins the enum with its writer, by BF:97's own reasoning, and **`schema_version` stays 1**: BF:97 makes the enum open so that this addition costs no version. It counts in its cell's denominator, never its numerator (BF §5). A backlog run refuses a unit outside its from-states, naming the status — `/docs-write` takes `missing` (and `captured`), `/docs-verify` `drafted`, `/docs-capture` `missing`.

### D7. Selection, consent and the unmerged-branch read

- **`<unit-id>`** is resolved against `units[].id` whole; a non-empty `blocked_by` is refused, naming the tokens (ROUTE:91).
- **`--next`** takes the first candidate in `priority` order, lowest number first (as BF:148 reads the threshold), then file order: status `missing` (and `captured`), `blocked_by` empty, `surface` a row of `surfaces[]` or `null` with evidence or a `journey` (BF:67-71), surface kind not `release` (D14), id in D13's class, and not moved on an unmerged branch (below). Ranking uses the backlog Phase 0 read; Phase 4 re-validates.
- **The unmerged-branch read.** Per-unit commits on unmerged branches create a trap ROUTE:110 does not name: the unit is still `missing` on the base and a run from there picks it again. So `--next` and `--batch`, before choosing: list `git -C <top> for-each-ref --sort=-committerdate --format='%(objectname) %(refname:short)' refs/heads refs/remotes/origin`; drop a name outside `workflows-core:read-only-repos` §3's branch class (`read-only-repos.md:62`) — counted, never printed — and HEAD's branch and the base; keep a ref not merged into the base whose backlog differs from the merge base's (`git diff --quiet <merge-base> <sha> -- .dev-workflows/docs-backlog.yml` exits 1); read the **first 20**, by object id only — `git show <sha>:.dev-workflows/docs-backlog.yml`, at most 1 MiB of it, into D13's line reader, which prints the candidate's `status`, `absent` or `unreadable`, never the file. A candidate whose status on such a ref differs from its own is skipped, naming the ref; an entry `absent` on a ref counts as not moved; a twenty-first ref is counted. **An unreadable ref is never silently skipped**: it is listed in the run's consent (Phase 3) before anything is written, so the operator decides with it in view. A forged ref can only make `--next` skip a unit or raise that warning, and says so.
- **`--batch <n>`**, `n` from 1 to 10 (one run's Opus spend, family D20), applies `--next`'s rule `n` times, excluding `tutorial` and `how-to` units (family D22). It places every unit, prints the list with Phase 3's consent fields per unit and the commands once, and asks `["Write these <n> units (Recommended)", "Cancel"]`. Each unit takes its own full gate; an escalation waits for its answer.
- **A unit that does not commit ends the batch** (D8); units already committed stand.

### D8. A unit moves only in the commit that finishes it

- **What permits the move**: a review that ended PASS, or PASS WITH RECOMMENDATIONS with every MAJOR survivor fixed or deferred by `doc-fixer` as needing a decision — carried, as `/document` carries one, to the report and the pull-request draft; a BLOCK cleared by the fix cycle's re-review or by *Manual fix notes* applied; or *Override* with its rationale recorded — and the last Phase 7 build passing. *Defer*, *Cancel*, a failing build or a stop do not.
- **What is written at Phase 9, and only then**: the page's `unit: <id>` frontmatter line, and the unit's `status` and, where it was `null`, `page_path` — then ST §7's commit-time ignore test and one commit by pathspec (D10). Neither line changes rendered output, so the last build stands. **A page that never reached Phase 9 carries no unit id**, so `/docs-audit --refresh`, which matches pages by that id (AUD:224), never finds it.
- **A targeted edit.** Only those two keys in the one entry whose `id` is the unit's change, the entry and its line range found by D13's line reader, whose shape test excludes the block scalars that could otherwise fake an entry; then `git diff -U0 -- .dev-workflows/docs-backlog.yml` must show hunks inside that range alone, else the run restores the content it read and stops, unstaged. No YAML parser ships with the plugin's scripts (`grep -rln 'import yaml' plugins/*/scripts` finds none).
- **A unit that does not commit** — single run or batch, a refused commit (a hook, FH:65) included — first loses any `unit:` line Phase 9 wrote; then every file the run created for it is moved, its relative layout kept, under `<top>/.dev-workflows/unfinished/<unit-id>/` — the first free `<unit-id>-<n>/`, `n` from 2, where that exists, never overwriting — outside the content root and the build; every file the run edited for it, a navigation config and the backlog alike, is restored to the content it read before the edit; and the run ends, naming that directory. Nothing is deleted, and the next run's strict build does not meet an omitted page (ST:466). **The clean-tree check never asks about it**: it reads the working tree with `':(exclude).dev-workflows/unfinished'`, and Phase 0 prints one line naming each unit directory there (D5). No stash takes it and no `.gitignore` is edited; the files stay visible and block nothing.
- **The other two commands** move a unit in the commit holding what justified it: `/docs-verify` the resolved page and the walk's results; `/docs-capture` the walkthrough, its `in-repo` images and `units[].walkthrough`.

### D9. What a drafted page carries

- **Reserved keys** `type`, `audience`, `visibility` from the unit at Phase 5, and `unit:` at Phase 9 (D8) — the first automated writer of `unit:` (FG:108).
- **`evidence:`** in EC §2's shape: `code` entries at the commit Phase 2 read, not the backlog's `sources[].ref` — EC:36 re-checks a page "at that `ref`, and at the current one"; a difference is reported and `sources[]` left to `/docs-audit` (BF:81). `artifact` entries at the specs commit read; a `walkthrough` entry where the unit has one.
- **`review_by`** from the surface's `volatility` — high 90 days, medium 180, low 365; `surface: null` 180 (FG:113). *Assumption:* the intervals; confirmed against a live run.
- **Markers.** Every claim the evidence does not ground carries `[NEEDS CLARIFICATION: <why>]` (EC:57). **And, recommended (question 2), one page-level marker** in the same vocabulary as the first line of the body (after the internal marker where there is one), saying the page has not been checked against the product. A code-first user page has had no claim resolved by its audience's method (EC:23), and neither has a code-drafted engineering page beyond the reviewer's spot checks; the marker tells a reader so — EC:59's "ships visibly marked", widened from a claim to a page — and it is what makes a page whose backlog move was lost in a merge land on `drafted`, not `published`, at the next `--refresh`, with no change to `/docs-audit` (AUD:224). `/docs-verify` removes it only in the commit that moves the unit to `verified`; until that command ships, only a person who walked the page does. With it, BF:122's premise is rewritten in sub-project 1: a backlog run's page always carries a marker until verified, so the publish edge reaches only a page a person tagged.
- **The internal marker** first after the frontmatter of an internal page (`references/docs-workflow/visibility.md:97-102`; :5 already asks it of this command).
- **Image slots** a walkthrough names become `<!-- docs-image-slot: <slot> -->` lines, the slot in D13's class. `/docs-verify`'s user walk fills them, as EC:95's "verification pass"; `/docs-write` places a captured unit's images from its walkthrough (sub-project 3). **Every command that places an image follows one set of rules**: `images.policy` — `in-repo` under `images.root`, or under the internal tree for an image only internal pages may see (ROUTE:155), one path per slot, within `images.max_bytes`; `object-store` and `cdn` commit nothing — and D12's fitness question, asked once per run over every image by path.
- **Navigation.** ST §4 gains an entry point, *regenerate*, run over the pages the commit will hold — tracked pages plus the unit's (ST:572's rule) — **only where every config a `builds[]` entry names carries ST §4's generated-block comment** (ST:502-503, :525-526; one config under `--public-only`, `commands/docs-init.md:108`). Where none qualifies, or the profile records no `builds[]`, the page is placed by the repository's own convention, as `/document` places one. It never branches on `generator` (`docs-profile-schema.md:104`). A new page takes no `order:`, so it sorts after every page that has one (ST:462). ROUTE:104's by-hand procedure remains for pages written any other way.
- **Frontmatter is not rendered provenance.** `workflows-core:doc-structure-conventions` §1 gains one sentence: the evidence contract's `unit:` and `evidence:` keys and the slot comment are outside it; `doc-reviewer`'s Source traceability row (:59), which grades a key "anywhere in a written file" and names the discrepancy marker "the one permitted comment", gains the same carve-out. That changes `/document` too, for a page already carrying `unit:` — a hand-tagged page, or one a backlog run wrote — where it removes a false MAJOR on `unit: U-001`, which `workflows-core:addressing` §1's grammar matches.

### D10. The docs-repository discipline

FH gains a section, *A backlog run's finish*, cited by all three commands:

- **The backlog must be committed** before the run's branch step: `git -C <top> status --porcelain -z -- .dev-workflows/docs-backlog.yml` empty and the file tracked, else a stop naming the commit to make. A stash would hide the file the run read; proceeding would fold the audit into a page's pull request. ROUTE:77 already asks for that commit (question 4).
- **Adopt or cut, once per run.** On the base or a detached HEAD the run cuts a branch from the base — resolved by `read-only-repos` §3's chain, named by `workflows-core:branch-naming` §1.4 (prefix fallback `docs/`; a profile's `branch_naming.pattern` wins), always confirmed. ### D11. `/docs-verify`'s contract

### D13. Untrusted input

The backlog is a tracked file any committer edits (CM:97); a walkthrough, a capture folder, a profile and a remote's ref names likewise. Every value read from them is data.

- **Resolved against a set.** A typed `<unit-id>` against `units[].id`, whole; an id held by two entries is a stop.

An artifact entry goes to D14's set and is never resolved as a clone. Every other entry is a **code entry**: its `repo` against `sources[].repo`, then the clone by `docs-profile-schema.md:100`'s order — **admitted only where its real path lies under `${REPOS_PATH:-/workspace}`, or the operator confirms it in this run's consent** — and refused where that clone is `$SPECS_PATH` or lies inside it. **`$SPECS_PATH`, and every path inside it, is never a `code-scanner` target**, so no scan reads, switches or pulls the specs checkout, its `security/` register included.
- **One line reader, one shape.** The duplicate-id check (D5), the unmerged-branch read (D7) and the targeted edit (D8) use one stdlib line reader, which accepts one shape: the units are block-style sequence entries directly under a top-level `units:` key, each opening `- id: <plain scalar>` at one indent, with `status:` a plain scalar on its own line inside the entry. An entry holding a block scalar (`|`, `>`), a flow mapping or sequence, an anchor, an alias or a tab — or a `units:` that is not block-style — is outside the shape, since a block scalar such as an edited `priority_reason` (BF:44) can hold lines that look like another entry. **On the working backlog an out-of-shape file is a stop before any write, naming the line. On a ref it is `unreadable`**, disclosed before consent (D7). A walkthrough id against the walkthrough directory's listing. A walkthrough id against the walkthrough directory's listing. A free-text answer normalised or re-asked (`escalation-rules` §0).
- **A class before a value reaches a path, a ref or a name.** A unit id, walkthrough id or slot: `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, else reported and never used. A ref: a full hex object name, `^[0-9a-f]{40}([0-9a-f]{24})?$`. A branch name: `read-only-repos.md:62`'s class, tested as it says, never only by `git check-ref-format`. A path: relative, no `..` segment, no leading `-`, no control character, inside its repository at the ref; a page path also inside the content root, `.md`, in BF §7's pair, **and its parent directory's resolved path inside the content root in the working tree**, so a committed symlink cannot carry it out. - **A unit id is not a key**: it matches `addressing` §1's grammar (`U-001` does) and never enters the run key set, `--commit-key` or a `[<key>]` subject.
- **Shell.** Values are single-quoted with each `'` written `'\''` (FH:132), placed after `--`, committed by `:(literal)` pathspec, messages through `-F` (FH:44-53); refs read by object id, never by an interpolated name. The profile's commands are the named exception (anti-goals).
- **Who sees what.** `code-scanner`: one source repository, the unit's titles, type and evidence paths. `doc-location-finder`: the docs repository and a composed summary. `doc-writer`, `doc-reviewer`: the unit brief — the unit, its surface row, scanner returns, artifacts' text, the walkthrough, the profile, the target — and in `/docs-verify` the recorded answers; never another unit. `docs-style-checker`, `doc-fixer`: the page and their findings. Each carries the family's untrusted-content block (e.g. `agents/doc-writer.md:102-137`), as every new agent will. Typed observed text, which a screen an attacker controls can supply, is written as a YAML string, shown quoted, handed over as data, and never reaches a shell; a screenshot an agent reads is data.
