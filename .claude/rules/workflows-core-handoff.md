# workflows-core — the `phase-handoff` authority

Loaded with `.claude/rules/workflows-core-git.md`, whose `paths:` it shares. Split out of that file to keep it under 20,000 characters; repo-wide rules are in `CLAUDE.md`; evidence is in `docs/maintainers/rationale.md`.

## Authority

`plugins/workflows-core/references/phase-handoff.md` is the **single source of truth** for the phase-boundary git entry points — `handoff-to-main` (§2, producer: its own generated file, which also holds §4.3's consent choice, a producer requesting it at its consent step and running §2 on the choice's first option) and `require-on-main` (§3, consumer: a twelve-state gate, its §3.3 table's rows H/I/G/A/B′/B/C′/C″/C/D/E/F; `require-on-main` reads its own generated file, `reference-parts/phase-handoff/require-on-main.md` — the gate and every rule its check applies, about half the reference — and serves a citation of a section that file holds, from its text, or the whole reference's, wherever the run has read either, else by reading it in a `##` section requesting it, and by reading the whole reference anywhere else, every other request reading the whole reference (the `reference` loader's entry-point rules, `skills/reference/entry-files.md`, which a request on `phase-handoff` reads with or before its other reads)) and `branch-check` (§6, its own generated file read the same way: at a run's start, a stop where the plugin branch it stands on is behind the default branch under its folder's root, and a question before its handoff would switch onto an open branch) — plus the eleven-prefix branch authority (`^(idea|prd|ard|spec|epics|design|ready|brd|frames|kb|conformance)/`, §1 rule 3), the repository pull-request template rule (§2.7.1), which the specs-repository handoff, `dev-workflows:code-handoff` §2.7 and `/document`'s keyed pull-request draft (`docs-workflows:finish-and-handoff` §5) follow, §3.4's row-F delegation table (an `absent` gated input falls back to the caller's own pre-existing behaviour, never a new prerequisite — the nine consumers with a row that stops instead, `/design`, `/update-spec`, `/prd-ground`, `/brd-split`, `/brd-interview`, `/brd-package`, `/brd-reconcile`, `/prd-proposal`, `/brd-proposal`, each gate an input that was never optional, `/brd-interview` beside a second row, on its parent's defect log, that falls back (count them with ``awk '/^### 3.4/{f=1} /^### 3.5/{f=0} f' plugins/workflows-core/references/phase-handoff.md | awk -F' \\| ' '/^\| `\// && $3 ~ /^\*\*stops/ {print $1}' | grep -o '`/[a-z:-]*`' | sort -u | wc -l``); and on the BRD route `/create-prd`, `/create-ard` and `/specify` split row F on a slice's `decisions.md` — no register falls back, while one present in the folder and on no ref stops), the §4.1 `Phase handoff:` outcome line, and the §4.3 consent choice. It inherits four of `specs-repo-git.md`'s hard rules — **the first three unchanged for every call against `$SPECS_PATH`** (rule 1 adds only §2.7.1's template reads, in the caller's repository) **and the fourth widened**, §1 rule 4 there adding `stash` and `checkout --` to the destructive-command list because a deliverable commit runs where the user's own work may be uncommitted and both of those discard it silently, and not taking the exception `specs-repo-git`'s rule 4 makes for its §4 step 6 replay (a deliverable push rejected as non-fast-forward is reported, never replayed) — and deliberately diverges on three (§1 rules 5–7: `require-on-main` is fatal by design, the deliverable commit carries a `Co-Authored-By` trailer, and `handoff-to-main` runs only behind the caller's own consent choice, never prompt-free).
