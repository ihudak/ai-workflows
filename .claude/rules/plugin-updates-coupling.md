# Plugin updates — which plugins to update together

Loaded when a plugin's `plugin.json`, the marketplace catalog or a plugin's `CHANGELOG.md` is read — where a release's version is bumped and its coupling bullet written — and read before writing an update command for someone to run (`.claude/rules/plugin-updates.md`, which holds the rest of the update rules). Split out of that file to keep it under 20,000 characters; evidence is in `docs/maintainers/rationale.md`. The bullets up to `workflows-core` 1.78.13 continue in `.claude/rules/plugin-updates-coupling-history-3.md` (1.75.0 to 1.78.13), `.claude/rules/plugin-updates-coupling-history-2.md` (1.59.0 to 1.74.0) and `.claude/rules/plugin-updates-coupling-history.md` (1.39.0 to 1.58.0), which share these `paths:` and load with this file; read all four.

**A release that relies on another plugin's newer text gets a bullet here**, naming the versions to install together and what each side does wrong beside an older other side, in both directions where both mislead. A batch that changes a `workflows-core` reference a dependent cites adds one (`docs/superpowers/reviews/2026-10-26-fix-batches.md`, *How to run a batch* step 6).
