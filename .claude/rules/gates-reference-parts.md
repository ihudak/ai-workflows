# Gates — the reference-parts gate

Loaded with `.claude/rules/gates.md`, whose `paths:` it shares and whose opening rule binds every gate. Split out of `.claude/rules/gates.md` to keep that file under 20,000 characters; repo-wide rules are in `CLAUDE.md`; evidence is in `docs/maintainers/rationale.md`.

## Reference-parts gate (`scripts/reference-parts.py`)

A split shared reference stays one source file under `plugins/workflows-core/references/`: a `<!-- reference-parts` declaration directly after its H1 line names its parts, and `<!-- part: <name> -->` … `<!-- /part -->` regions say which part owns each line. `generate` assembles each requestable part — with the always part, the parts it needs, the reference's rule index and a line under its title naming every part the file holds — into a committed file under `plugins/workflows-core/reference-parts/<name>/`, and deletes every file there that no declaration produces. A `helper` part is covered and may be named in `needs=`, but has no file and is never requested: its text reaches a run only inside a part that brings it, directly or through a part it needs, and the rule index sends each of its rules to those parts, as a failure naming one does. Each index name is a code span, so a heading starting with a number never renders as a nested list. **A generated file is never edited by hand**: edit the source and run `generate`. The marker syntax, the index's name matching and the generated layout are written in the script's own docstring and nowhere else. It is a script of its own, never a check in `scripts/check-docs.sh`, whose body the internal editions share byte for byte. ([why](../../docs/maintainers/rationale.md#reference-parts))

**An entry-point file is the narrower mechanism, for a reference that does not load by part.** A `<!-- reference-entry-files` declaration directly after its H1 line names each entry point that gets a file, and the sections that file holds — `entry <entry> holds=<§>,…` whole, `partial <entry> <§> "<phrase>" …` in part — and `<!-- entry: <entry> -->` … `<!-- /entry -->` regions select the lines; a line outside every region belongs to no entry file. `generate` writes `plugins/workflows-core/reference-parts/<ref>/<entry>.md`, the regions' text in source order under a line naming every section the file holds. There is no rule index and no placement: the loader serves the file for a request naming the entry point and for a citation of a section it holds — a lookup, served from the file's text wherever a read of it, or of the whole reference, made in the run is in the conversation, and otherwise by reading it in a `##` section that requests the entry point and the whole reference anywhere else — and the whole reference for any other request or citation. The loader keeps those rules in its entry-point rules, `plugins/workflows-core/skills/reference/entry-files.md`, which a request on that reference reads first unless they are in the conversation word for word; the loader's own body, which comes with every request, names the entry points with a file of their own, each file's path and that rules file, and nothing more. One is declared, `phase-handoff require-on-main` ([why](../../docs/maintainers/rationale.md#reference-parts)).

**`check-parts`** fails on a malformed declaration or marker, a non-blank line outside every region, a nested region or one closed inside a fenced block, anything but exactly one `always` part, a need that names no part, a helper marked `always` or `private` or brought by no requestable part of its own reference, one rule name in two parts, a relative link in a split source, and a generated file that is stale, missing or produced by no declaration — it regenerates in memory and compares byte for byte. A positional pointer inside a part (*above*, *below*, *the next section*) prints as a `FLAG` line and does not fail. On an entry-point declaration it also fails on an entry declared twice or naming no entry point of its reference, a `partial` line naming an undeclared entry, a § no heading opens with, a section held whole declared beside one it is, lies under or has under it, a non-blank line of a section held whole outside every region of its entry, a region line inside a numbered section its entry declares neither whole nor in part, and a `partial` phrase no region text of that section holds — a phrase naming a numbered rule, `rule <N>`, is held only by a region line there opening the rule's own item, `N.`, never by a mention of the rule in the section's opening line; a positional pointer in an entry region prints as a `FLAG` too. Its `PASS` line counts the split references, the entry-point files and every generated file.

**`check-citations`** fails when the loader skill's split list is not the declared set; when a file in a dependent plugin's `commands/`, `agents/` or `references/` cites a split reference without the load-by-part preamble as a paragraph of its own; on a part request naming no requestable part — a helper included; on an entry-point request, `args: "<ref> <token>"` on a reference that does not load by part, whose token is not the first word of a code span in one of that reference's headings outside a fenced block — the loader stops the run on it — printing the `entry-point requests` census beside the per-reference one, a first token naming no reference file being check 16's; on an explicit part request whose sentence names a rule that the loads of that sentence's calls do not hold — each part with its needs, or the whole reference where one of those calls loads it: a call converted to the wrong part; in a paragraph citing a split reference, in any form, on a sentence naming one of its rules, other than as that sentence's own citation of it, that no load made at or before the sentence holds — an explicit part or whole load, or the parts a bare citation is placed on, of any split reference the paragraph cites whose index holds the name, never a later load, since a run applies a rule as it reads it; and on a rule held in a private part, named by an explicit or a bare citation or by any other sentence of such a paragraph, whose text no part load brings. A run reads a sentence whole before it acts, so the calls of one sentence are one load in any order, and a rule named before its parenthetical call is held by it. An `index` request is a lookup — the run loads what the index then names — so its own sentence passes whatever public rule it names, and its load holds every later sentence of the paragraph. A sentence citing a split reference is judged as that citation for the names that reference's index holds. A `§` reference belongs to a reference citation, split or not — a `<plugin>:<name>` token naming a reference file of that plugin the tree holds (a directory is not one: a command or skill shares its name), a loader call, a call of a skill the script's `SKILL_REFERENCES` ties to the one reference it loads (`model-routing` → `model-routing/classification`), or a path: the one a `§4 of <citation>` phrase names, with nothing between the number and "of", or a `§ <Name> of <citation>` phrase where `<Name>` is a section of that reference — in its index if split, else a heading of its file; else the nearest before it in its sentence; else the first after it there; else, in a sentence citing nothing, the nearest in an earlier sentence of its paragraph, against whose loads alone it is then read; else none, and it names nothing. So a `§4` after a call of an unsplit reference names no split reference's rule. A name holding a code span is read with it, and a possessive `§ <Name>'s` (or `’s`) is read as the section `<Name>`. A bare citation is placed on the part of each rule its sentence names, on every one where it names rules of several, since the preamble has the run load each before applying its rule; one naming no rule the index holds is placed on the whole reference, which is what the preamble then loads, so it passes too, and it holds every later sentence of its paragraph as that whole load. Both count in the `placed N, whole M` census printed per reference, and `--verbose` lists each whole one. **A paragraph making no part request is read for its other sentences too**: that reading was first refused as firing only on correct prose, and re-measured on the tree before the rule-by-rule reading four of its six hits were gaps that reading found, so it is on ([why](../../docs/maintainers/rationale.md#reference-parts)). **A part file is read by path only inside `workflows-core`**: `check-citations` fails a `reference-parts/<ref>/<part>.md` path in a dependent plugin's `commands/`, `agents/` or `references/`, naming the loader call to make instead, since `${CLAUDE_PLUGIN_ROOT}` there is that plugin's own root, which holds no `reference-parts/` — check 16 matches `references/` paths only, and `scripts/check-docs.sh` is not widened for this. Where an entry point is declared, `check-citations` also fails when the loader skill's paragraph opening `These entry points read their own file:` does not name the declared set or the entry-point rules file; when that file is missing, or its sentence ``The file for `<ref> <entry>` holds …`` names other sections than the generated file's own line under its title; and when the loader skill itself carries such a sentence, which belongs to the rules file alone.

**The out-of-file check** (`check-citations`, where an entry point is declared) holds a command to what the loader serves from that file. In a `##` section requesting `args: "<ref> <entry>"`, each sentence citing `<ref>` — a `workflows-core:<ref>` token, a loader call or a path — or carrying a `§` that belongs to a citation of `<ref>` by the rule above is judged by its numbered `§` references of `<ref>`: each passes where it lies under a section the entry holds whole, or is a section held in part and the sentence holds one of its phrases; any other fails, `cites workflows-core:<ref> §<n>, which the <entry> file does not hold, in a section that reads only that file`, and a sentence citing `<ref>` by no `§`, with no request of the entry point among its calls, fails the same way `with no section`. A whole load at or before the sentence in its section — `args: "<ref>"`, or a request of an entry point with no file of its own — holds every `§`, never a later one. Before the first such section in its file, a citation of `<ref>` fails whatever it names, unless its own sentence loads the whole reference, because the run would load the whole reference ahead of the request. After the first such section, outside every section requesting the entry point and until the file's first whole load of `<ref>` — the first sentence whose calls load it whole — each sentence citing `<ref>` is judged the same way against the file the run already holds, and fails with the tail *after the first `##` section requesting `<ref> <entry>` and before any load of the whole reference in this file* in place of *in a section that reads only that file*, because a citation of a section the file does not hold, or of none, loads the whole reference there; that load's own sentence passes, and nothing after it is read. Whole loads are counted from calls alone, never from a citation the check fails. The census `entry-point file <ref> <entry>: N request section(s), M citation(s) checked` prints, and a tree declaring no entry point runs none of this.

**`check-questions`** gates the question rules: a command in `workflows-core`'s or a dependent plugin's `commands/` whose text holds a `choices:` line, fenced or not, a line naming both `phase-handoff` and `§4.3` — the consent array `/frames` presents with no array of its own — or a line stating a prompt of 2–4 options the command builds at run time, `2–4 options` on a line naming no `` `choices` `` array — `/feedback`'s grouped metadata prompt, and the target prompt of `/prompt`, `/prompt-brainstorm` and `/prompt-grill-me` — fails unless a **step** starts on an earlier line than the first such line: a paragraph or list item outside every fenced block that opens with `**Load the question rules.**` and holds `Skill(skill: "workflows-core:reference", args: "escalation-rules core")`. A line naming `` `choices` `` arrays beside `2–4 options` states the arrays' rule ("Use `` `choices` `` arrays; 2–4 options"), not a prompt, and is no question: counting it failed `/security-workflows:scan`, whose preamble states that rule ahead of its step, on correct prose. A citation of that part inside a rule statement is no step, since a run reads it as a source note, and neither is a step inside a fence, which a run prints. The first question is a line, not a phase, so a question above a command's first `##` heading needs the step above it. It prints the census `question rules: N command(s) present a choice list, M load the rules first`, and `--verbose` lists each command's step and first-question lines. It is a subcommand of its own because its subject is a command's questions, not a reference's declaration: inside `check-citations`, its fail-closed rule would fail every fixture tree that declares parts and asks nothing ([why](../../docs/maintainers/rationale.md#reference-parts)).

**The three gating subcommands fail closed**: `check-parts` and `check-citations` fail when no reference carries a reference-parts declaration, `check-citations` also fails on a declared reference no dependent plugin cites, and `check-questions` fails when its scan finds no command presenting a choice list. Entry-point files are outside the first guard: a tree declaring none passes their checks. But `check-citations` fails a declared entry point that no `##` section of a scanned file requests, since its out-of-file check would judge nothing.

`.github/workflows/validate-catalog.yml` runs its `--selftest` — one fixture tree per case under `scripts/fixtures/reference-parts/`, each case asserting the exit code, what it must print and, for a red case, its number of problems — and its `run:` steps say which subcommands run on every push. No case count is written here: `--selftest` prints one `ok` line per case.

**What it cannot see:** whether a run loads a part when it reaches the citation — the preamble tells it to, and the rule-by-rule reading and the live runs check that it does. It reads a rule's name only as an italic, bold, backticked or quoted span, or a `§` reference that belongs to the citation, in the citation's own sentence — and in the other sentences of a paragraph that cites a split reference — so a citation naming its rule another way ("rule 6", "the overflow rule") counts whole, and the census is how such citations are found; it gives a `§` reference to a citation by position, and by the words beside it only in a `§4 of <citation>` phrase or a `§ <Name> of <citation>` one naming its section, so "`§4`, which `workflows-core:gamma` defines" written after a call of a split reference belongs to that call, and a `§` in a sentence citing nothing, with no citation before it in its paragraph, names nothing, so one leaning on a later sentence's call goes unread; a bare citation it counts whole holds every later sentence of its paragraph, though a run that reads its rule by a name the gate cannot read loads only that rule's part; an explicit request whose sentence names no rule is placed on the part it requests, whichever that is, so a call converted to the wrong part passes there — each `next-phase-offer` lane request names its lane's rule in its sentence (`next-phase-offer dev`, the *Dev — build, verify & deliver* lane) so the gate places and pins it, and a request written without one is held by review alone; and whether a flagged pointer crosses a part boundary is the reading's call, not the gate's. **The out-of-file check** gives a `§` to a citation by the same position, so a `§` a sentence means as another reference's — "emit its §5 notice" after a citation of `<ref>`, or a `§` after a bare `<name>.md`, which is no citation — is judged as `<ref>`'s and fails where the file lacks it, and a pointer into `<ref>` in a sentence citing nothing, with no citation before it in its paragraph, goes unread. It reads a `§` by its number only, so a held section cited by name alone — "`workflows-core:phase-handoff` § Stop contract" — fails as citing no section: a documented false positive, with no site in the tree, worked around by citing the number. It reads a file in the order of its text, so a section a run reaches before an earlier one — a definition a later phase invokes — is judged by where it stands. It judges a file by its own text alone, never by the references it loads: a command's section loading another reference is not judged for that reference's citations of `<ref>`, and a reference is judged only where it requests the entry point itself, so one reaching `<ref>` by a path or a citation, with no request of its own, goes unseen. Whether a failing sentence only explains or applies a rule the file lacks is the reading's call; it fails both. **`check-questions`** cannot see whether a run executes the step when it reaches it, nor whether the step's text is the agreed paragraph, since it reads only the lead and the call; a question asked in prose with no array and no option count, ahead of the step, goes unseen, and so does a prompt stated on a line that also names a `` `choices` `` array, read as the arrays' rule; a line that only mentions `choices:`, or `2–4 options` without that rule's subject, counts as a question, erring early.
