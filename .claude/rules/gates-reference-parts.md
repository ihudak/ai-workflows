# Gates — the reference-parts gate

Loaded with `.claude/rules/gates.md`, whose `paths:` it shares and whose opening rule binds every gate. Split out of `.claude/rules/gates.md` to keep that file under 20,000 characters; repo-wide rules are in `CLAUDE.md`; evidence is in `docs/maintainers/rationale.md`.

## Reference-parts gate (`scripts/reference-parts.py`)

A split shared reference stays one source file under `plugins/workflows-core/references/`: a `<!-- reference-parts` declaration directly after its H1 line names its parts, and `<!-- part: <name> -->` … `<!-- /part -->` regions say which part owns each line. `generate` assembles each requestable part — with the always part, the parts it needs and the reference's rule index — into a committed file under `plugins/workflows-core/reference-parts/<name>/`, and deletes every file there that no declaration produces. A `helper` part is covered and may be needed, but has no file and is never requested: its text reaches a run only inside a part that needs it, and the rule index sends each of its rules to those parts. Each index name is a code span, so a heading starting with a number never renders as a nested list. **A generated file is never edited by hand**: edit the source and run `generate`. The marker syntax, the index's name matching and the generated layout are written in the script's own docstring and nowhere else. It is a script of its own, never a check in `scripts/check-docs.sh`, whose body the internal editions share byte for byte. ([why](../../docs/maintainers/rationale.md#reference-parts))

**`check-parts`** fails on a malformed declaration or marker, a non-blank line outside every region, a nested region or one closed inside a fenced block, anything but exactly one `always` part, a need that names no part, a helper marked `always` or `private` or brought by no requestable part, one rule name in two parts, a relative link in a split source, and a generated file that is stale, missing or produced by no declaration — it regenerates in memory and compares byte for byte. A positional pointer inside a part (*above*, *below*, *the next section*) prints as a `FLAG` line and does not fail.

**`check-citations`** fails when the loader skill's split list is not the declared set; when a file in a dependent plugin's `commands/`, `agents/` or `references/` cites a split reference without the load-by-part preamble as a paragraph of its own; on a part request naming no requestable part — a helper included; on an explicit part request whose sentence names a rule that the loads of that sentence's calls do not hold — each part with its needs, or the whole reference where one of those calls loads it: a call converted to the wrong part; in a paragraph making explicit part requests of a reference, on a sentence naming one of its rules, other than as that sentence's own citation of it, that no load made at or before the sentence holds — an explicit part or whole load, or the parts a bare citation is placed on, of any split reference the paragraph cites whose index holds the name, never a later load, since a run applies a rule as it reads it; and on a rule held in a private part, named by an explicit or a bare citation or by any other sentence of such a paragraph, whose text no part load brings. A run reads a sentence whole before it acts, so the calls of one sentence are one load in any order, and a rule named before its parenthetical call is held by it. An `index` request is a lookup — the run loads what the index then names — so its own sentence passes whatever public rule it names, and its load holds every later sentence of the paragraph. A sentence citing a split reference is judged as that citation for the names that reference's index holds. A `§` reference belongs to a reference citation, split or not — a `<plugin>:<name>` token naming a reference file of that plugin the tree holds (a directory is not one: a command or skill shares its name), a loader call, a call of a skill the script's `SKILL_REFERENCES` ties to the one reference it loads (`model-routing` → `model-routing/classification`), or a path: the one a `§4 of <citation>` (or `§ <Name> of <citation>`) phrase names; else the nearest before it in its sentence; else the first after it there; else, in a sentence citing nothing, the nearest in an earlier sentence of its paragraph, against whose loads alone it is then read where the paragraph requests a part of that reference; else none, and it names nothing. So a `§4` after a call of an unsplit reference names no split reference's rule. A name holding a code span is read with it, and a possessive `§ <Name>'s` (or `’s`) is read as the section `<Name>`. A bare citation is placed on the part of each rule its sentence names, on every one where it names rules of several, since the preamble has the run load each before applying its rule; one naming no rule the index holds is placed on the whole reference, which is what the preamble then loads, so it passes too, and it holds every later sentence of its paragraph as that whole load. Both count in the `placed N, whole M` census printed per reference, and `--verbose` lists each whole one. **A paragraph making no part request is not read for its other sentences**: measured over the live tree with the four rulebooks trial-split, that widening fired only on correct prose ([why](../../docs/maintainers/rationale.md#reference-parts)). **Both subcommands fail closed**: either fails when no reference carries a declaration, and `check-citations` also fails on a declared reference no dependent plugin cites.

`.github/workflows/validate-catalog.yml` runs its `--selftest` — one fixture tree per case under `scripts/fixtures/reference-parts/`, each case asserting the exit code, what it must print and, for a red case, its number of problems — and its `run:` steps say which subcommands run on every push. No case count is written here: `--selftest` prints one `ok` line per case.

**What it cannot see:** whether a run loads a part when it reaches the citation — the preamble tells it to, and the rule-by-rule reading and the live runs check that it does. It reads a rule's name only as an italic, bold, backticked or quoted span, or a `§` reference that belongs to the citation, in the citation's own sentence — and, where a paragraph makes explicit part requests, in its other sentences — so a citation naming its rule another way ("rule 6", "the overflow rule") counts whole, and the census is how such citations are found; it gives a `§` reference to a citation by position, and by the words beside it only in a `§4 of <citation>` phrase, so "`§4`, which `workflows-core:gamma` defines" written after a call of a split reference belongs to that call, and a `§` in a sentence citing nothing, with no citation before it in its paragraph, names nothing, so one leaning on a later sentence's call goes unread; in a paragraph requesting one reference, a citation-free sentence whose `§` leans on an earlier bare citation of another split reference is not read; a bare citation it counts whole holds every later sentence of its paragraph, though a run that reads its rule by a name the gate cannot read loads only that rule's part; and whether a flagged pointer crosses a part boundary is the reading's call, not the gate's.
