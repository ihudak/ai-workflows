# docs-workflows — the docs backlog: `/docs-audit` and the backlog runs

Loaded with `.claude/rules/docs-workflows.md`, whose `paths:` it shares. Split out of `.claude/rules/docs-workflows.md` to keep that file under 20,000 characters; the plugin's other rules are there; repo-wide rules are in `CLAUDE.md`; evidence is in `docs/maintainers/rationale.md`.

## Invariants

- **`plugins/docs-workflows/references/docs-audit/backlog-format.md` §1's line shape, `plugins/docs-workflows/references/docs-audit/evidence-contract.md` §4's walkthrough shape and `plugins/docs-workflows/scripts/backlog-lines.py` change in one commit.** Two shapes, and the script is the one implementer of both: the paragraph *The line shape a backlog run reads.* states the backlog's, and every line-wise read or edit a backlog run makes of `.dev-workflows/docs-backlog.yml` goes through the script; *The shape a walkthrough is read in.* states a walkthrough's — that paragraph's line rules and a walkthrough's own structure — and no program parses a walkthrough but the script, and no command writes one but through its walk verbs. Its `--selftest` pins the script to both paragraphs — it reads each paragraph's out-of-shape reasons, §1's schema, and §4's example and stamp, from the references themselves, and fails where any disagrees with the script. It also holds `finish-and-handoff.md` §6.4's quote of the one stderr line that has a caller restore the backlog, byte for byte, so that line and the script's text change together; and it holds the phrase by which `plugins/docs-workflows/references/docs-iteration/backlog-run.md`'s two programs, §10.1's read and §10.2's test, which `/docs-workflows:docs-write` runs at its Phase 0 and Phase 9 and `/docs-workflows:docs-verify` at its Phase 0 and Phases 1 and 4, and `docs-verify.md`'s own marker program, which removes the marker, find the page-level marker in `evidence-contract.md` §3 — in that section directly before the marker, and in the three programs, byte for byte, `docs-write.md` holding no program that searches by it — and the visibility marker `<!-- docs-visibility: internal -->` that §10.2's program and `docs-verify.md`'s marker and frontmatter programs match as page text — in `visibility.md` §5 on a line of its own, and in each of those programs, byte for byte. `backlog-run.md` holds, once, the steps the backlog runs share, and a command cites its sections with its parameters, which it names once in its own body, keeping there each stop line and what it does with a section's result. `moved`'s `--own-moves` and `edit`'s `--from`, `--walkthrough` and `--block` are tested by the same `--selftest`, which pins `moved`'s output without the flag to a literal, byte for byte, and `/docs-workflows:docs-write` passes none of the four, and `/docs-workflows:docs-verify` passes `--own-moves` under `--next`, `--from` on each edit, `--walkthrough` on a user unit's move, its walk's record and its prepare commit's edit where the unit does not name its walkthrough, and `--block` on an unresolved record. The `--selftest` also pins the image-slot comment, `unit-brief.md` §3.3 step 5's, to `docs-verify.md`'s slot program. `.github/workflows/validate-catalog.yml`'s *Self-test the backlog line reader* step runs it on every push. `export`, which writes a source repository's commit as regular files for `claim-reader`, lives in this script; it is the one program that reads a source repository for that agent, as an argument list to git, never through a shell. ([why](../../docs/maintainers/rationale.md#docs-backlog-shapes))
- **`plugins/docs-workflows/references/docs-iteration/unit-brief.md` §1 holds, once, the list of the sections a backlog run's brief replaces in `doc-writer` and `doc-reviewer`.** Each agent carries one pointer paragraph, *A backlog run's brief.*, which sends a brief carrying `brief_kind: unit` as a top-level field of its own to that file and restates none of the list; a brief without that field — every `/document` dispatch — reads both agents as they stand. An edit to any section §1 names, or to either agent's inputs, steps or dimension table, re-reads it in the same change — `unit-brief.md` whole, not §1 alone, since six of its paragraphs say how a section §1 does not name reads under a unit brief: §2's *Phase numbers*, §3.1's last paragraph, §4.1's *The page is what is graded.* and §4.3's *A marked claim, in the dimensions that stand.*, and, under an apply brief, §3.4's *The steps that stand.* and §4.6's *The dimensions that stand.* — so that a section renamed, renumbered, added or split either joins §1 or still reads true under a unit brief.
- **A unit moves only in the commit that finishes it.** `/docs-workflows:docs-write` writes the unit's move — its `status`, and its `page_path` where that was unset, through `backlog-lines.py edit` — and the page's `unit:` frontmatter line at its commit step, `/docs-write`'s Phase 9, never earlier, and commits both with the page and its navigation in one commit (`plugins/docs-workflows/references/finish-and-handoff.md` §6.3); `doc-writer` never writes `unit:` (`unit-brief.md` §3.3). A unit that does not commit loses that line, its created files move under `.dev-workflows/unfinished/` and its edited files are restored (§6.4). An edit that writes either earlier, or commits a move apart from its page, breaks this. `/docs-workflows:docs-verify`, which writes no `unit:` line, moves a unit as the bullet on its move below says. ([why](../../docs/maintainers/rationale.md#docs-backlog-move))
- **A backlog run's docs-repository finish is `finish-and-handoff.md` §6.** It offers one push, with consent, after its last unit (§6.5), and prints the pull-request draft in its report, writing it to no file (§6.6); it opens no pull request. It writes no file into a source repository it grounds on, the docs repository itself excepted where it is also one, and no specs deliverable — no deliverable, deliverable branch or branch prefix in `$SPECS_PATH`, where it writes bookkeeping alone.
- **A backlog run reads one kind of specs document — an `ard.md` under `$SPECS_PATH`'s `specifications/` tree, at `<default-ref>` alone — and never makes the specs checkout a `code-scanner` target.** The set is the one file `/docs-workflows:docs-audit`'s `decision` kind enumerates. `/docs-write` holds every artifact entry to the `ARTIFACT_PATH` class of `plugins/docs-workflows/references/docs-iteration/backlog-run.md` §3 before anything uses it, and reads an admitted one by `git -C "$SPECS_PATH" show '<commit>:./<path>'`, `<commit>` what `<default-ref>` — the last `specs-git start` JSON's `default_ref` — resolves to, never from the working tree: a copy there that the commit lacks is named in one `Specs:` line and not read (`backlog-run.md` §5 step 3 and §8, which `/docs-write`'s Phase 1 *Sources* and Phase 4 step 1 run). Where it cannot read so — `$SPECS_PATH` unset, empty or no git repository, `specs_git: blocked` or `misrooted`, no `default_ref` — the unit is refused. `$SPECS_PATH`, a path inside it and a clone whose tree holds it are refused as scan targets, and where `$SPECS_PATH` is unset or empty a `decision` or `release` surface's entries are artifact entries, refused, never sorted as code, and a clone is scanned only where a code-kind surface's evidence names its `sources[]` entry, since the audit records the specs tree's entry with or without a surface naming it (`backlog-run.md` §5 steps 2 and 5). An edit that widens the set, reads it off `<default-ref>`, or lets a scan reach the specs checkout breaks this. ([why](../../docs/maintainers/rationale.md#docs-backlog-specs))
- **`unit-brief.md` §1 and §2.1 are the apply brief's one copy.** A brief carrying `answers` as a top-level field of its own besides `brief_kind: unit` is an apply brief, `/docs-workflows:docs-verify`'s: §1 says, entry by entry, which section of `doc-writer` and `doc-reviewer` its §3.4 or §4.6 replaces under one, and §2.1 gives its fields — the answers, a walked page's coverage map, the page as it stood before the run's first edit, a repair's findings and the fixers' reports, each data. One passage of §2.1 has a second copy: the rule for when a walkthrough step states a claim, with what an instruction's own effect is, which `walkthrough-composer` carries in its Method step 3, since it cannot read this file, and which `backlog-lines.py`'s `--selftest` (`states_definition_pinned`) holds equal to §2.1's, byte for byte. **An apply brief adds no `brief_kind`**: each agent reaches it through its one pointer paragraph on `brief_kind: unit`, as the bullet on `unit-brief.md` §1 above says, and a brief without `answers` — every `/docs-write` dispatch — reads both agents by §3.1, §3.2, §3.3, §4.1, §4.2, §4.3, §4.4 and §4.5 alone, never by §2.1, §3.4 or §4.6. **`doc-fixer` is never handed answers**: a finding on an answer's application goes back to `doc-writer`, under the same brief, and every other to `doc-fixer`. An edit to §3.4 or §4.6 re-reads `unit-brief.md` whole, as that bullet says.
- **`/docs-verify` moves a unit in the one commit that holds its resolved page.** It writes the move — `status: verified`, from `drafted`, through `backlog-lines.py edit --from drafted --status verified` — at its Phase 10, once every claim on the page is resolved, the answers applied and the page through its style, build and review gates, and commits the page and `.dev-workflows/docs-backlog.yml` — with a user unit's images and changed walkthrough — together in one `verify` commit (`finish-and-handoff.md` §6.3); it never writes `unit:`, which the page has carried since its drafting. **The page-level marker leaves only by this command's own marker program**, in `remove` mode, at its Phase 6, once `doc-writer` has applied the answers and before any gate; Phase 10 runs it again in `check` mode, with the frontmatter program, and either failing ends the unit. Neither `doc-writer` nor `doc-fixer` removes it — `unit-brief.md` §3.4 and `doc-fixer`'s dispatch text say so — and a unit that ends after Phase 6 has its page restored from its copy (§6.4) — or, where that cannot be done, left as it stands and reported as not verified. **`--from` refuses an entry another writer moved meanwhile** (`status-differs`), a unit-level end with the backlog as it was. A unit whose claims do not resolve does not move: its `record` commit holds the backlog alone, `blocked_by: [claims-unresolved]` written by `edit --from drafted --status drafted --block claims-unresolved` (`backlog-format.md` §4). A walk ending without the move takes no token: its `record` commit holds the walkthrough and the backlog — at a prepare's own end, its `prepare` commit, the walkthrough stamped and holding no result. An edit that removes the marker anywhere else, commits the move apart from the page, or drops `--from` breaks this. ([why](../../docs/maintainers/rationale.md#docs-backlog-verify))
