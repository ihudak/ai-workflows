# docs-workflows — the docs backlog: `/docs-audit` and the backlog runs

Loaded with `.claude/rules/docs-workflows.md`, whose `paths:` it shares. Split out of `.claude/rules/docs-workflows.md` to keep that file under 20,000 characters; the plugin's other rules are there; repo-wide rules are in `CLAUDE.md`; evidence is in `docs/maintainers/rationale.md`.

## Workflow map

```
/docs-audit          → [resolve-docs-repo (signal-positive)] → resolve <top> + read the profile → [confirm/record source_repos[] where the key is absent — recorded only where a profile exists] → [require nothing on main: this command gates on no prior phase] → [code-scanner×N over the recorded repos (parallel, cap 4, default branch — the session's own repository on another branch read there by ref, `workflows-core:scan-refresh`'s fixed-policy case) + the caller's own $SPECS_PATH read for the `decision` and `release` kinds] → [§8.5 seeded round 2; a theme still unresolved is named, never flattened into a gap] → [docs-auditor: surfaces[] with volatility from git log density] → [ia-planner@Opus: cross each surface with the types it earns, rank on four signals, propose tutorial candidates] → [mint a picked tutorial candidate — --refresh only] → write .dev-workflows/docs-backlog.yml + reconcile existing pages by their `unit:` frontmatter key → [docs-audit-reviewer@Opus] → [triage: verify each finding; the orchestrator applies survivors — no fixer and no re-review (D25)] → impl-maintenance → commit-artifacts   (no branch and no commit in the docs repo: the backlog is left in the working tree for the operator to review and commit; resolves no docs grounding (`.claude/rules/docs-grounding.md`); its cost and feedback land under $SPECS_PATH/documentation/<docs-repo-slug>/, ahead of pending, because this run has no PRD and never will — D19; report-only if misrooted)
                      └── docs-auditor (docs-workflows)       (used by /docs-audit)
                      └── ia-planner (docs-workflows)         (used by /docs-audit)
                      └── docs-audit-reviewer (docs-workflows) (used by /docs-audit)
/docs-write          → [resolve-docs-repo (signal-positive)] → <top>, the work tree's top level → specs-preflight (keyless) → read the profile, each command and content root held to a class → [backlog and profile committed — finish-and-handoff §6.1] → backlog-lines.py check → [toolchain preflight] → [the page-level marker read from evidence-contract §3] → select: <unit-id> | --next | --batch ≤10 (the unit tests; --next and --batch pass over a unit an unmerged branch's backlog moved — backlog-lines.py moved) → resolve sources (code clones; an ard.md at <default-ref> alone) → [doc-location-finder, per unit with no page_path] → one consent (pages, placement targets, clones, artifacts, every profile command verbatim) → branch once (§6.2: adopt or cut) → per unit: [re-check on the branch] → [code-scanner×N (≤4 per response, one round, default branch — <top>, and the session's own repository off its default branch, read by ref)] + the ard.md read at <default-ref> → [doc-writer@Opus under a unit brief: the page, and its entry on each placement target] → [docs-style-checker] → [doc-fixer] → regenerate the navigation where every builds[] config carries the generated block → builds (one doc-fixer pass on a content failure) → [doc-reviewer@Opus] → [triage: verify each finding] → [doc-fixer] → the page-level marker tested → unit: + backlog-lines.py edit → one commit (§6.3) | a unit-level end (§6.4: created files under .dev-workflows/unfinished/, edited files restored; the batch ends) → [one consented push (§6.5); the pull-request draft printed (§6.6)] → impl-maintenance → commit-artifacts   (never opens a pull request; resolves no docs grounding (`.claude/rules/docs-grounding.md`); its cost and feedback land under $SPECS_PATH/documentation/<docs-repo-slug>/, ahead of pending, because this run has no PRD and never will — D19; report-only if misrooted)
```

## Invariants

- **`plugins/docs-workflows/references/docs-audit/backlog-format.md` §1's line shape and `plugins/docs-workflows/scripts/backlog-lines.py` change in one commit.** The paragraph *The line shape a backlog run reads.* states the shape, and the script is its one implementer: every line-wise read or edit a backlog run makes of `.dev-workflows/docs-backlog.yml` goes through it. Its `--selftest` pins the script to the paragraph — it reads the paragraph's out-of-shape reasons and §1's schema from the reference itself and fails where either disagrees with the script — so a reason added to one and not the other turns the build red. It also holds `finish-and-handoff.md` §6.4's quote of the one stderr line that has a caller restore the backlog, byte for byte, so that line and the script's text change together; and it holds the phrase by which `plugins/docs-workflows/references/docs-iteration/backlog-run.md`'s two programs, §10.1's read and §10.2's test, which `/docs-workflows:docs-write` runs at its Phase 0 and Phase 9, find the page-level marker in `evidence-contract.md` §3 — in that section directly before the marker, and in both programs, byte for byte, `docs-write.md` holding no program that searches by it — and the visibility marker `<!-- docs-visibility: internal -->` §10.2's program matches as page text — in `visibility.md` §5 on a line of its own, and in that program, byte for byte — so a reword of either side turns the build red rather than ending every unit after its review. `backlog-run.md` holds, once, the steps the backlog runs share, and a command cites its sections with its parameters, which it names once in its own body, keeping there each stop line and what it does with a section's result. `moved`'s `--own-moves` and `edit`'s `--from`, `--walkthrough` and `--block` are tested by the same `--selftest`, which pins `moved`'s output without the flag to a literal, byte for byte, and `/docs-workflows:docs-write` passes none of the four. `.github/workflows/validate-catalog.yml`'s *Self-test the backlog line reader* step runs it on every push. `export`, which writes a source repository's commit as regular files for `claim-reader`, lives in this script so that the same step runs its cases; it is the one program that reads a source repository for that agent, as an argument list to git, never through a shell.
- **`plugins/docs-workflows/references/docs-iteration/unit-brief.md` §1 holds, once, the list of the sections a backlog run's brief replaces in `doc-writer` and `doc-reviewer`.** Each agent carries one pointer paragraph, *A backlog run's brief.*, which sends a brief carrying `brief_kind: unit` as a top-level field of its own to that file and restates none of the list; a brief without that field — every `/document` dispatch — reads both agents as they stand. An edit to any section §1 names, or to either agent's inputs, steps or dimension table, re-reads it in the same change — `unit-brief.md` whole, not §1 alone, since six of its paragraphs say how a section §1 does not name reads under a unit brief: §2's *Phase numbers*, §3.1's last paragraph, §4.1's *The page is what is graded.* and §4.3's *A marked claim, in the dimensions that stand.*, and, under an apply brief, §3.4's *The steps that stand.* and §4.6's *The dimensions that stand.* — so that a section renamed, renumbered, added or split either joins §1 or still reads true under a unit brief.
- **A unit moves only in the commit that finishes it.** A backlog run writes the unit's move — its `status`, and its `page_path` where that was unset, through `backlog-lines.py edit` — and the page's `unit:` frontmatter line at its commit step, `/docs-write`'s Phase 9, never earlier, and commits both with the page and its navigation in one commit (`plugins/docs-workflows/references/finish-and-handoff.md` §6.3); `doc-writer` never writes `unit:` (`unit-brief.md` §3.3). A unit that does not commit loses that line, its created files move under `.dev-workflows/unfinished/` and its edited files are restored (§6.4). So a page that never reached its commit step carries no unit id, and `/docs-workflows:docs-audit --refresh`, which matches a page to its unit by that id, never finds it. An edit that writes either earlier, or commits a move apart from its page, breaks this.
- **A backlog run's docs-repository finish is `finish-and-handoff.md` §6.** It offers one push, with consent, after its last unit (§6.5), and prints the pull-request draft in its report, writing it to no file (§6.6); it opens no pull request. It writes no file into a source repository it grounds on, the docs repository itself excepted where it is also one, and no specs deliverable — no deliverable, deliverable branch or branch prefix in `$SPECS_PATH`, where it writes bookkeeping alone.
- **A backlog run reads one kind of specs document — an `ard.md` under `$SPECS_PATH`'s `specifications/` tree, at `<default-ref>` alone — and never makes the specs checkout a `code-scanner` target.** The set is the one file `/docs-workflows:docs-audit`'s `decision` kind enumerates. `/docs-write` holds every artifact entry to the `ARTIFACT_PATH` class of `plugins/docs-workflows/references/docs-iteration/backlog-run.md` §3 before anything uses it, and reads an admitted one by `git -C "$SPECS_PATH" show '<commit>:./<path>'`, `<commit>` what `<default-ref>` — the last `specs-git start` JSON's `default_ref` — resolves to, never from the working tree: a copy there that the commit lacks is named in one `Specs:` line and not read (`backlog-run.md` §5 step 3 and §8, which `/docs-write`'s Phase 1 *Sources* and Phase 4 step 1 run). Where it cannot read so — `$SPECS_PATH` unset, empty or no git repository, `specs_git: blocked` or `misrooted`, no `default_ref` — the unit is refused. `$SPECS_PATH`, a path inside it and a clone whose tree holds it are refused as scan targets, and where `$SPECS_PATH` is unset or empty a `decision` surface's entries are artifact entries, refused, never sorted as code (`backlog-run.md` §5 steps 2 and 5). So no scan reads, switches or pulls the specs checkout, and no other specs document reaches a page — one reason a `release` unit is refused (`/docs-write`'s Phase 1 unit test 4): reading its `release-notes.md` would add a third reader to the two that `workflows-core:phase-handoff`'s row for that file names as not reading the working copy. An edit that widens the set, reads it off `<default-ref>`, or lets a scan reach the specs checkout breaks this.
- **`unit-brief.md` §1 and §2.1 are the apply brief's one copy.** A brief carrying `answers` as a top-level field of its own besides `brief_kind: unit` is an apply brief, `/docs-workflows:docs-verify`'s: §1 says, entry by entry, which section of `doc-writer` and `doc-reviewer` its §3.4 or §4.6 replaces under one, and §2.1 gives its fields — the answers, the page as it stood before the run's first edit, a repair's findings and the fixers' reports, each data. **An apply brief adds no `brief_kind`**: each agent reaches it through its one pointer paragraph on `brief_kind: unit`, as the bullet on `unit-brief.md` §1 above says, and a brief without `answers` — every `/docs-write` dispatch — reads both agents by §3.1 to §4.5 alone, never by §2.1, §3.4 or §4.6. **`doc-fixer` is never handed answers**: a finding on an answer's application goes back to `doc-writer`, under the same brief, and every other to `doc-fixer`. An edit to §3.4 or §4.6 re-reads `unit-brief.md` whole, as that bullet says.
